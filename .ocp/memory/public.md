# Project memory — public lessons (committed)

## Build, dev, test

- This repo is bun-first: all scripts use `bun --filter`; pnpm ignores the root `workspaces` field (no pnpm-workspace.yaml), so `pnpm install` silently skips backend/frontend deps. Use `bun install && bun run build`. Common: `bun run typecheck` (after every code change), `bun run build` (tsc -p backend && vite build frontend — vite does NOT typecheck frontend), `bun test backend/tests`.
- App version lives in root package.json — never hardcode. Backend reads at runtime via backend/src/version.ts; frontend gets it injected at build time via Vite define __APP_VERSION__.
- Backend serves frontend/dist via readFileSync per request — frontend changes go live at http://127.0.0.1:3000 after `bun run build` with NO gateway restart. Gateway does NOT hot-reload backend config (Orchestrator snapshots this.config at construction); only proxy hot-applies via initProxyConfig, capture via CaptureRecorder.applyConfig.
- saveConfig is a shallow merge `{...current, ...newConfig}` — any nested section is REPLACED wholesale; partial-field editors MUST round-trip the rest (`tiers.exclude` was the exact footgun).
- GET /api/ui/config returns { status, config } envelope; frontend api.getConfig() unwraps to RouterConfig directly — consumers must treat the result as the config object (not the envelope).
- OpenCode user config: two files — providers in ~/.config/opencode/opencode.jsonc under the SINGULAR `provider` node (JSONC; use jsonc-parser text-level modify/applyEdits to preserve comments), credentials in ~/.local/share/opencode/auth.json. Provider CRUD via backend/src/opencode/user-config.ts.

## Frontend conventions

- All dropdowns render through frontend/src/components/Combobox.tsx (portal + z-index 220 + ARIA combobox), never native <select>. Filter input auto-appears only when options.length > 8. For toggles use Switch.tsx. Global ConfirmProvider/ToastProvider in App.tsx — use `useConfirm()` / `useToast()`; never window.confirm/alert.
- Z-index scale: page-level modals 100, feature dialogs 200, nested sub-dialogs 210, Combobox panels 220, global confirm 300, toasts 400 (topmost). All fixed-overlay dialogs MUST use createPortal(..., document.body) — non-none backdrop-filter makes an element the containing block for fixed descendants. All modal overlays must lock body scroll via useBodyScrollLock(active).
- All list pagination renders through the shared Pagination component (frontend/src/components/Pagination.tsx): callers pass page/pageSize/total/onChange — server-side pages re-fetch in onChange, client-side re-slice. Ladder [10,20,50,100,200].
- All console "Test" connectivity-probe logic lives in frontend/src/lib/useModelTest.ts — never re-inline.
- Model edit form exists as two parallel implementations — ProviderModelsDialog.tsx nested add/edit form (provider page) and ModelEditDialog.tsx (/models page); same PATCH payload, so any new form field must be mirrored in BOTH files.
- Console UI 禁止用 emoji 做图标/标题前缀，一律用 lucide-react 组件（含 i18n locale 文案——emoji 历史上藏在 locales/*.ts 文本里）。唯一例外是主题选择器 7 色主题名的色点 emoji（🖤🌌💚🟣🌹⚪🟡）。Console UI 文案禁止出现内部文档记号（ADR-xxxx 编号等）—— ADR 编号只留在代码注释与 docs。"请求捕捉" 是该功能命名（不要改成"归档/存档"）。User-facing copy must not leak implementation details.
- i18n `\n` is conditional — RulesPage line ~383 etc. add whiteSpace:'pre-line' to the container so `\n` renders as real line breaks; CombosPage/OverviewPage containers do NOT, so `\n` collapses to single spaces. Multi-line hint/desc needs BOTH i18n `\n` AND container `whiteSpace:'pre-line'`.
- App-shell is fixed-viewport: body/#root/Layout root lock to 100vh with body overflow:hidden, <main> (overflowY:auto) is the global scroll container; pages needing internal scrollbars (logs/captures) use height:'100%' on their root.
- Frontend fonts are self-hosted via @fontsource (no external CDN — required for offline/intranet/mainland-China). Font-family stacks must end with generic CJK fallbacks (Noto Sans SC/Microsoft YaHei/sans-serif).
- ClientsPage (/clients) uses full-width accordion rows — collapsed header shows brand icon/name/truncated config path/status badge/quick takeover button; first un-hooked client auto-expands only when nothing is hooked.
- UI placement: inbound forward-proxy ("proxy access") settings live on /proxy-access (ProxyAccessPage.tsx) under Client Access nav group next to /clients — NOT on /proxy (outbound-only) and NOT inside ClientsPage.

## Theming

- Theme system standardizes on 10 shared visual tokens (--card-shadow/-hover, --btn-bg/-hover, --btn-primary-text/-shadow/-shadow-hover, --focus-ring, --scrollbar-thumb/-hover) defined in every [data-theme] block in frontend/src/styles/index.css. Visual language: soft shadow + hairline border + inset top highlight + 4% SVG noise in --bg-gradient (light: 3%).
- Amber theme FINAL (3 user A/Bs): accent amber-600 #d97706 + white primary-button text #ffffff (3.2:1 accepted). amber-700+white and yellow-600+black were both rejected. #d97706 is the user's locked gold — do NOT propose deepening, brightening, or hue-shifting. Primary-button text color must be the contrast-optimal choice per theme — bright accents take dark text, deep accents take white; never unify all buttons to white.
- Theme portfolio is a 7-color system: 黑=obsidian 🖤, 蓝=indigo 🌌, 绿=cyber 💚, 紫=violet 🟣, 红=sunset 🌹 (rose-monochrome), 黄=amber 🟡, 白=light ⚪. Hue themes are dark hue-tinted; neutral themes (black/white/amber) keep near-neutral bases. Theme-dependent colors in TSX must come from CSS variables.

## Backend / architecture

- POST /api/ui/restart is `setTimeout(() => process.exit(0), 500)` with NO self-respawn — only works when started by ocr daemon (sign: ~/.opencode-router dir exists); manually-started gateway dies for good. Always poll /health and start out-of-band (`nohup bun backend/src/index.ts`) if it stays down.
- Gateway port single source of truth is config.yaml `port` (loadConfig().port); client-hook adapters and daemon tooling derive base URLs via defaultGatewayPort() (backend/src/cli/clients/base.ts). Known bug: startDaemon({port}) is ignored — backend/src/index.ts listens on loadConfig().port (YAML wins over PORT env).
- server.ts auth-hook whitelist derives console page paths from SPA_ROUTES in routes/console.ts (single source of truth) — when adding a new console page, add it ONLY to SPA_ROUTES; a hand-copied whitelist previously drifted and 401'd browser refreshes on /models and /tiers. Auth policy: console pages + browser-fetched read-only endpoints (/v1/sessions, /v1/traces, /v1/health/*, /v1/models) are open; ONLY inference endpoints require API keys.
- Frontend api.ts ↔ backend resilience type mirroring is brittle — BreakerInfo must mirror CircuitBreakerSnapshot/CircuitBreakerSummary field-for-field. One historical rename made /guardrails breaker matrix render blank, TS did NOT catch it (loose structures both sides). When adding fields, grep ALL frontend files for BreakerInfo/CircuitBreakerSummary.
- Fastify under Bun: `onSend` hooks MUST be callback-style `(req, reply, payload, done) => done(null, payload)` — the async form causes ERR_HTTP_HEADERS_SENT double-sends on responses sent from preHandler. `app.addHook('onClose')` is the server-SHUTDOWN hook, not a request-lifecycle hook; client-abort detection needs `reply.raw.on('close')`.
- Bun 1.3.14 node:tls quirks — do NOT refactor backend/src/forward-proxy MITM back to SNICallback / tlsServer.emit('connection', socket) / TLSSocket.pipe(): Bun lacks SNICallback, ignores synthetic 'connection' emits, TLSSocket.pipe() may not flush buffered data. Committed architecture (per-host tls.Server + explicit certs + manual ClientHello SNI probing + loopback splice + data-relay with resume) is verified — keep it.

## Routing

- Tier policies page at /tiers (renamed from /rules); /rules client-side redirects to /tiers. Tier composition policies (config.tiers per-tier priceRange/blacklist/whitelist/weights) applied inside ProviderRegistry.getCandidateModelsForTier + weighted primary pick. blacklist/whitelist mutually exclusive (UI-enforced; blacklist wins if both appear).
- Client model selection is SLOT-BASED only: each client adapter declares model slots (claude: main/smallFast; opencode: main→model + subagent→agent.general.model; codex: main→model), setup writes concrete ids or 'auto'. Gateway-side: registered model IDs = exact pass-through; unregistered names = classifier decides. A glob modelMap tier-hint layer (routing.modelMap) was built and removed the same day — do not reintroduce.
- Routing execution is UNIFIED: all entry modes resolve to one candidate chain consumed by PipelineOrchestrator.executeCandidatePool(request, {chain, tier, allowEscalate, attemptCap, label}, captureOut). CircuitBreakerManager.isAvailable() is a NON-consuming peek; only the execution gate calls canExecute() (HALF_OPEN canary). Last candidate always force-tried.
- "缓存" = ROUTING DECISION CACHE (Layer2Judge LRU+TLS over sha256(userText), stats at GET /api/ui/cache-stats routingCache). Three distinct things — do NOT conflate: (1) routing decision cache, (2) response-level fuzzy semantic cache (banned — system-prompt vector dominance caused 0.99 cosine cross-contamination), (3) session sticky = ADR-0006 ratchet. classifier.layer2.decisionCache.{enabled,ttlSeconds,maxEntries} defaults enabled=true/1800s/500.
- Config removed in 2026-10-07 cleanup (do not reintroduce): (1) prompt-override rules (config.rules / keyword→tier / deny 403 / PromptRulesCard); (2) budget enforcement (config.budget); (3) static config.yaml `providers:`/`models:` nodes — runtime list synced from opencode daemon, providers via boot-direct.ts (ADR-0011). Hand-written YAML `rules:`/`budget:`/`providers:`/`models:` are silently ignored or stripped on save.
- ADR-0011 superseded daemon execution: gateway runs PURE DIRECT inference — index.ts builds pool via backend/src/providers/boot-direct.ts from opencode.jsonc + auth.json + models.dev catalog. Wire per model = providers/wire.ts wireFor(model-level provider.npm > config npm > provider npm). Executors: openai/anthropic/responses (@ai-sdk/openai → POST {base}/responses)/google; vertex/bedrock/azure = unroutable; OAuth excluded until P2. Per-wire mount translation is permanent (Zen anthropic → /inference/anthropic/v1/messages).
- Variant support (2026-10-10): /v1/models lists `<base>-<variant>` siblings; requests accept sibling or `<base>#<variant>` (unknown → 404); variant effort wins over client reasoning_effort; X-OCR-Variant header. Variants ingested at boot only — restart required after editing.
- Outbound proxy: config.yaml `proxy:` = {enabled(默认false), url(默认http://127.0.0.1:7890), whitelist[], blacklist[]}; pattern matches provider/model combo AND bare model id (anthropic/* = provider-level, */claude-* = model-level, no wildcard = substring). Resolution: blacklist → whitelist → url → direct. localhost/127.0.0.1/::1 never via proxy. Proxy is the ONLY hot-apply config section. Implementation: backend/src/utils/proxy.ts.
- OpenCode zen free models cannot be reached directly: FreeTierError locks free tier to the official client (gate validates UA/x-opencode-session/stream/tools; since 2026-09 gate moved to /inference lane, zen/v1 hard-blocks free). Official third-party channel is OpenCode Go (https://opencode.ai/zen/go/v1, $10/month, in models.dev as opencode-go, headers via opencode.jsonc options.headers x-opencode-session). zen/v1 delisted ids fail and trigger failover.

## Observability

- Console observability is session-dimension only: SessionsPage at /sessions is the merged page (old SessionsPage + TracesPage were deleted; /usage and /traces redirect there; i18n namespace renamed usage.* → sessions.* — do not reintroduce usage keys). /v1/traces endpoint kept for CLI debugging. Traces persist to SQLite (~/.opencode-router/traces/traces.db); boot replay repopulates the in-memory LRU; retention sweep runs at boot + hourly.
- FinOps cumulative persistence: only totalRequests + fallbackCount survive process restart (finops_totals table). All other FinOps fields are process-local and reset to zero on restart by design. Implementation: backend/src/trace/persist.ts openFinOpsStore(dir) (independent bun:sqlite handle on shared file; sweep() deletes only `traces`).
- Capture record fields (2026-10-08): request (pre-compression) + upstreamRequest (snapshot of request sent to last attempted candidate — written on SUCCESS inside executeCandidatePool AND on failure paths when failoverAttempts>0; absent only on zero-attempt failures) + upstreamError ({status,provider,modelId,body}) + response (verbatim; never add upstreamResponse). Compressed tool outputs carry `[token-saver: ...head/tail...]` as anti-loop escape hatch.
- Capture archive limits (user-confirmed): maxTotalMB 2048 / maxBodyBytes 524288 — intentional debug-fidelity tradeoff, not a typo; don't revert. Capture is HOT-APPLIED via CaptureRecorder.applyConfig() — toggle/params take effect immediately, no gateway restart.
- OpenCode /catalog source "disabled" semantics: disabled = excluded from OCR aggregation AND from auto-sync/boot-network ONLY — in-memory payload is retained (setSourceEnabled no longer deletes remote state), manual refreshSource works (no 400), refreshAll covers ALL sources, boot start() hydrates disabled sources cache-only (no network).

## Reasoning effort vocabulary

- 6-level ladder aligned with OpenCode. `EFFORT_LADDER = ['none', 'low', 'medium', 'high', 'xhigh', 'max']` is the full wire vocabulary. `none` is rank 0 (the "no thinking" tier), NOT a default/placeholder/switch. `ReasoningEffort = (typeof EFFORT_LADDER)[number]` is a 6-value union — never introduce an `EffortLevel` intermediate that excludes `none`. Wire fields (reasoning_effort, reasoning.effort, supportedReasoningEfforts, downgrade inputs/outputs, actualEffort, response headers) all use the 6-value vocabulary. The 5-value subset `['low','medium','high','xhigh','max']` is a SEPARATE dimension — the default `supportedReasoningEfforts` for thinking-capable models (since `none` is a client-side toggle, not a model capability). Do NOT extract `EFFORT_LEVELS_EXCLUDING_NONE` as a derived constant. Distinguish omitted (`undefined`) from explicit `'none'`. Provider builders (anthropic, google) guard with `(effort && effort !== 'none') || explicitBudget != null`; openai-compatible and responses pass `request.reasoning_effort` verbatim.

## Testing

- Backend e2e tests hitting inference endpoints can't override disk config.yaml's apiKeys — server.ts preHandler falls back to disk config. Tests must mirror server.ts's same fallback: read loadConfig().apiKeys, pick the first enabled key, build the Authorization header (see combo.test.ts authHeaders()). Don't modify server.ts or delete user config to make tests pass.
- For backend server integration tests needing deterministic registry models: pass `models: []` in test RouterConfig + mockMode=true — ProviderRegistry's constructor seeds fixed tier models (mock-lite/mock-plus/mock-pro/mock-ultra). Don't use loadConfig().models as an id source (real config.yaml may have zero models).
