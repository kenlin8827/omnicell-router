# ADR-0008: Top-Tier Industrial-Grade Model Circuit Breaking, Multi-Level Failover and Health Management System

## Status
Accepted & Implemented - 2026-09-30
**Amended 2026-10-14** — breaker state is persisted to disk (see §Amendment). The original in-memory-only posture is superseded: cooldowns, backoff position, sliding windows and manual trips now survive a gateway restart.

**Amended 2026-10-14 (rules)** — every automatic trip rule of §1/§2 became individually enable-able with its own parameters under `circuitBreaker.rules`, HALF_OPEN became a configurable trial batch, and `circuitBreaker.shadow` added rules-validate-without-blocking. Nothing about the defaults changed: an absent `rules` tree reproduces the pre-amendment behavior byte-for-byte (see §Amendment (2026-10-14, rules)).

## Context
In large-scale production-grade AI gateway and model-routing gateway practice, upstream LLM services are strongly heterogeneous, cross-vendor and highly volatile, facing many unavoidable availability challenges:

1. **Quota Exhausted**: an account suddenly falls into arrears or its token quota is used up (HTTP 402 / `insufficient_quota`). Without perception, the gateway keeps hammering that model with the full subsequent request flood, failing every one of them.
2. **Multi-Hour Vendor Outages (5-Hour Outages)**: upstream service avalanches (500/502/503/504 / network timeouts). Without a circuit breaker, every request waits for tens of seconds to time out, draining the gateway's connection pool and dragging downstream clients down.
3. **Rate Limiting (429)**: on TPM / RPM overruns, without short backoff, the gateway cannot offload traffic onto alternate models within the same Tier.
4. **Session Ratchet Deadlock**: Session model locking (Pinning) was introduced earlier to protect KV Cache hit rate, but when the pinned model goes down, every subsequent turn of that session is completely paralyzed.
5. **Mis-tripping caused by client mistakes**: a client sending an over-long context (400 context length exceeded) or being blocked by safety filtering is a user-input problem — it must never be wrongly counted as a model failure or cause the model to trip its breaker.

## Decision
Build an industrial-grade resilience system end to end: **a high-precision Error Taxonomy, a multi-level Circuit Breaker state machine, Same-Tier transparent failover and Session Self-Healing**:

### 1. Structured Error Taxonomy (Error Taxonomy & Diagnosis)
Upstream anomalies are strictly decomposed into 6 classes, each governed differently:
* `QUOTA_EXHAUSTED` (HTTP 402 / `insufficient_quota`): **immediate Hard Open**, entering a long cooldown (default 12 hours); no high-frequency probing; supports manual reset from the admin backend;
* `AUTHENTICATION_ERROR` (HTTP 401 / `invalid_api_key`): **immediate hard open**, locked until the key is reloaded;
* `RATE_LIMITED` (HTTP 429 / TPM/RPM): **instant adaptive backoff**, preferentially parsing the `Retry-After` header, briefly steering clear while alternate same-Tier nodes take over;
* `SERVICE_UNAVAILABLE` (HTTP 5xx / network timeout / ETIMEDOUT): **sliding-window + consecutive-failure-threshold trip**, entering stepped exponential backoff (30s → 60s → 120s ... capped at a maximum of 5 hours);
* `CLIENT_ERROR` (HTTP 400 / context length exceeded): **zero-penalty pass-through**, not counted as a model failure, triggers no retry and no breaker trip;
* `UNKNOWN`: standard fault-tolerant retry.

### 2. Standard Three-State Circuit Breaker State Machine
* `CLOSED` (healthy): carrying traffic normally;
* `OPEN` (tripped): blocking requests to that model, diverting to alternate models instantly at zero added latency;
* `HALF_OPEN` (probing): after the cooldown expires, admit a trickle of canary (Canary) requests to probe. If probing succeeds, fully restore `CLOSED`; if it fails, double the cooldown duration and `OPEN` again.

### 3. Transparent Same-Tier Candidate Pool Failover (Zero-Downtime Failover)
* Each Tier maintains a prioritized candidate list (`primary`, `backup-1`, `backup-2`);
* Requests are dispatched to the primary model first; when the primary throws a recoverable failure (402/503/429), the breaker records the fault and, **within the same HTTP session, transparently transfers to a same-Tier backup model at millisecond latency**;
* The user receives a 200 success response unaware, with governance trace metadata attached in the response headers:
  * `X-OCR-Failover: true`
  * `X-OCR-Failover-Attempts: 2`
  * `X-OCR-Failover-Path: primary-model -> backup-model`
  * `X-OCR-Breaker-State: CLOSED`

### 4. Session Monotonic Ratchet Self-Healing (Session Self-Healing)
* When the `pinnedModel` bound to a session is detected to have entered the `OPEN` tripped state, the gateway automatically unbinds it and smoothly migrates/re-pins (Repin) the session to a healthy same-Tier backup model, eliminating the deadlock entirely.

### 5. Full-Spectrum Observability and Admin Interfaces (Observability & REST APIs)
* `GET /health`: intelligently summarizes the gateway's global health (`ok` / `degraded` / `outage`) and breaker health counts;
* `GET /v1/health/circuit-breakers`: exposes all models' live state, remaining cooldown duration, failure class, total request/failure counts;
* `POST /v1/health/circuit-breakers/reset`: provides administrators a one-click reset endpoint after manual recharging or vendor-side troubleshooting is complete.

## Consequences and Impact
- **Positive impacts**:
  - Ends for good the fragility of "a model falling into arrears or being down for 5 hours taking the whole service with it", achieving true 99.99% enterprise-grade high availability;
  - Zero-configuration transparent disaster recovery: clients use the gateway like a standard OpenAI API, while multi-vendor seamless switching happens automatically underneath;
  - Precisely protects upstream billing and connection-pool resources, eliminating sustained avalanche traffic toward dead upstreams.

## Amendment (2026-10-14) — Breaker Memory Survives Restart

**Problem.** The state machine lived only in process memory, so every restart wiped all cooldowns: a 402 quota trip (12h) or an operator manual trip (up to 7d) was silently undone, and a freshly booted gateway re-hammered accounts still inside their cooldown window. The registry's own docstring delegated persistent exclusion to `config.tiers` — a workaround for the gap, not the intent.

**Decision.**

- `<OCR_HOME>/breaker-state.<env>.json` (version 1, **per environment** — unlike the suspect flags, which stay GLOBAL because an account is suspect wherever it is used, breaker memory keys on model ids that belong to the ACTIVE env's config; restoring under env B prunes env A's records and the first save would rewrite the file, so one shared file would make an env switch destroy the other book-set's memory). It carries the full mutable state of every model and pair breaker: state, consecutive counts, totals, sliding window, `cooldownUntil`, the backoff position (`currentCooldownMs`), probe counters and the trip reason triple. Same file doctrine as `suspect-accounts.json` (atomic temp+rename, mode 0600, load-once, a corrupt file starts with empty memory and is renamed `.corrupt.<ts>` aside on the first write).
- **Write timing**: every public mutation entry point arms a ~1s debounced snapshot; a `process.on('exit')` hook flushes synchronously — signal handlers never run for `process.exit()` (the console's restart route exits exactly that way), and 'exit' also covers SIGINT/SIGTERM/SIGBREAK paths plus natural termination. Hard kills (`taskkill /F`, power loss) have no handler: the debounce window is the honest loss bound there (the governance-overlay doctrine: a brief loss is under-shaping, not a lie). A failed save keeps the snapshot for the next mutation or the exit retry — one transient write error (AV holding the rename target, momentary ENOSPC) does not silently drop a trip.
- **Restore ordering**: the boot path attaches the store AFTER all config models are registered and drops records for models the current config no longer knows (self-cleaning, no ghost breakers). Identity (provider/tier) always comes from the CURRENT config; the file's copy is display-only. The restored `cooldownUntil` is clamped to `now + currentCooldownMs` so a wall-clock **rewind** while the gateway was off cannot stretch a cooldown past its ladder position; a clock **forward jump** shortens it — fail-open, the same pre-amendment behavior a live process would show, noted rather than fixed.
- **Trust boundary**: illegal state values, reason codes/categories outside the closed vocabulary, non-primitive `reasonParams` entries and non-numeric scalars are sanitized at load; a malformed record is dropped, never fatal, and a save failure degrades to a warning — the gateway keeps running on in-memory breakers. A file that EXISTS but cannot be READ (EACCES, transient AV lock) starts empty **loudly** and is preserved aside on the first write, never silently overwritten.
- **No config flag, default-on** — consistent with `suspect-accounts.json`, which was always persisted. The payload stays display-safe (model ids, provider, keyHash prefixes, classifier reason text; never key material) — with the honest caveat that classifier `reason` strings embed up to ~150 chars of upstream response body, the same text already exposed in console snapshots; mode 0600 is best-effort (a no-op on Windows, real ACLs would need icacls).
- The consuming gate (`canExecute` probe-slot consumption) and the lazy OPEN→HALF_OPEN transition do NOT schedule writes on their own; a consumed canary slot normally ends in `recordSuccess`/`recordFailure`, which does. A debounced save or the shutdown flush can still land mid-canary and persist an exhausted HALF_OPEN quota, so `applyRecord` refreshes the probe quota when restoring a HALF_OPEN record — a restart can never strand a breaker in HALF_OPEN (worst case: one extra canary after the restart).
- A successful canary recovery (HALF_OPEN→CLOSED) also re-arms the sliding window EMPTY: stale failures from the outage must not let one transient blip re-trip the model the moment it recovers (the consecutive-failure count resets as before; the fresh window earns its rate threshold back from zero).

**Consequences.**

- (+) Quota/rate cooldowns, the escalation ladder and manual trips survive restarts; recovery probing resumes exactly where the previous lifetime left off.
- (+) CLOSED-state failure accumulation survives too (consecutive counts and the sliding window are no longer reset by a restart).
- (−) The file lives under the GLOBAL state root and is raced by concurrent gateway instances sharing one `OCR_HOME` — the same accepted stance as the suspect flags (single-process is the product form).
- (−) A manual trip is no longer "cleared on gateway restart": a forgotten trip cools until its own cooldown expires; permanent exclusion still means `config.tiers` exclude lists.

## Amendment (2026-10-14, rules) — Per-Rule Trip Configuration, HALF_OPEN Trial Batch, Shadow Mode

Spec: [docs/design/circuit-breaker-rules-config.md](../design/circuit-breaker-rules-config.md) (v3.1). This amendment changes **which edges an operator can switch off and with what parameters**; the taxonomy of §1, the three-state machine of §2 and the failover contract of §3 are untouched — `category` and `isRetriable` are never rewritten by a rule toggle, so failover behavior is rule-independent.

**Problem.** §1/§2 stated the trip behaviors as constants. 402 and 401 always hard-tripped (and the 401 always flagged the account), a long `Retry-After` always hard-tripped at a boundary borrowed from the retry config, and both statistical detectors always ran; the only master lever was `circuitBreaker.enabled`, which is all-or-nothing. Recovery was a hardcoded single canary closing on its first success, too coarse to validate a model that several credentials serve. And a new ruleset could only be judged by letting it block live traffic.

**Decision.**

- **One rule tree, three families, resolved once at startup.** `circuitBreaker.rules.counting.*` decides **what is even recorded as a failure** (`serverErrors`, `unknownErrors`, `clientErrors` each with `enabled` + `minCooldownMs`; 429 countedness has **no** toggle — the classifier counts every 429, `rateLimitErrors` owns only the no-`Retry-After` floor); `rules.trip.*` decides **when a counted failure opens the circuit** (`quota`, `auth`, `rateLimit`, `consecutiveFailures`, `failureRate`, each with `enabled`, its own parameters and a `scope` override); `rules.recovery.*` is the HALF_OPEN/full-open policy. `circuitBreaker.shadow` and `circuitBreaker.persistence.debounceMs` sit beside the tree. Every unset parameter falls back to the global knob of §1, which the rules page shows read-only in its **shared defaults** disclosure (live value per `auto` field, config key on hover; the knobs themselves stay YAML-only, `activeProbing.intervalMs` being the one exception), and `resolveCircuitBreaker` merges `rules`, each family map and each rule object **key-by-key** — a partially written rule block can never drop its siblings' defaults against the shallow top-level merge. Cross-field clamps are enforced in both the sanitizer and the resolver: `recovery.halfOpen.maxProbes >= 1`, `successThreshold <= maxProbes`, `trip.failureRate.minCalls <= windowSize`.
- **Rules are applied at the manager gate, never in the classifier.** `CircuitBreakerManager.applyFailure` is the single join point for the orchestrator AND `ActiveHealthProber` (the prober calls `classify()` without circuit config, so classifier-internal gating would be bypassed by exactly the path that drives recovery). A diagnosis is resolved into one dispatch — `drop` / `hard` (with a final duration) / `count` (an adjusted **copy**) / `as-is` — and delivered to every breaker in the blast radius. The caller's diagnosis object is never mutated.
- **Hard-trip durations are resolved by the gate, not proposed by the classifier.** `trip.quota.cooldownMs` / `trip.auth.cooldownMs` give the 402/401 block length (default `quotaCooldownMs`, the 12h of §1); a hard 429 gets `max(trip.rateLimit.minCooldownMs, min(Retry-After, global maxCooldownMs))` — the clamp ceiling stays global because it caps *any* derived cooldown. The `trip.rateLimit.hardTripAboveMs` boundary re-derives at the gate (default borrowed from `retry.inplace.maxRateLimitWaitMs`; overriding it deliberately decouples the breaker-side boundary from the in-place-retry decision, which the breaker never rewrites). Accordingly `ErrorDiagnosis.suggestedCooldownMs` was renamed **`minCooldownMs`** and is now a floor for the **statistical path only** (`max(minCooldownMs, computed ladder/rate cooldown)`); it can no longer steer a hard trip.
- **OFF means different things per family, and that difference is the contract.** Counting-off = the class is never recorded (no window entry, no consecutive count); a dropped class still releases any HALF_OPEN probe slot it consumed, so a non-penalty outcome can never strand a trial. Detector-off = recording continues unchanged, the check is simply never evaluated (documented, and pinned by tests). `trip.rateLimit` OFF **downgrades** a long-`Retry-After` 429 to a counted statistical failure rather than ignoring it, and the `Retry-After`-derived floor still flows through `max(min, computed)`. `counting.clientErrors` ON is the only inversion: 400/422 become counted failures (`shouldTripBreaker: true`) on the tripping rule's own ladder.
- **Zero automatic tripping is a five-switch predicate.** Automatic tripping is off if and only if all five `trip.*` switches are off — counting-off is NOT a route to zero, because counted 429 has no toggle and still feeds the detectors. `getRulesStatus()` computes `on | partly_off | all_off` (+ `shadow`) from exactly those five switches and the whole effective ruleset rides the `/api/admin/status` payload the console reads, so the UI banner and the rules page can never disagree with the gate. Caveat recorded honestly: this predicate counts rules that *fire*; a breaker already OPEN keeps walking its own recovery ladder (a `maxWaitMs` or short-batch re-OPEN is that state machine's edge), and manual trips are operator intent outside the predicate.
- **Closing a rule reconciles live and persisted state.** `restoreState()` skips OPEN records whose `reasonCode` belongs to a disabled rule (`breaker.quota`, `breaker.auth`, `breaker.rate_limit`, `breaker.consecutive`, `breaker.rate_window`) — otherwise a restart would resurrect a 12h quota block nobody asked for, since restart is the only apply point. `breaker.canary` (a trigger wrapping whatever cause rode along) and `breaker.manual` (operator intent) deliberately never reconcile: such a record expires on its own cooldown or is cleared by a manual reset. Existing SUSPECT flags likewise **survive** every toggle (see below).
- **HALF_OPEN is a trial batch.** `recovery.halfOpen.maxProbes` is the concurrent trial budget (default `halfOpenMaxProbes`, and now also the prober's per-model per-cycle budget via `getProbeBudget()`); `successThreshold` is how many successes the batch needs before the breaker closes — the close still re-arms ladder + window empty as before. A success below the threshold releases its own slot so the batch keeps dispatching. Under credential attribution a pair success **counts as a model trial success** instead of force-closing the model breaker. `BreakerRecord` and the snapshot gained `halfOpenSuccesses` and `halfOpenEnteredAt` (no half-open entry timestamp existed before); `applyRecord` refreshes probes, successes **and** the entry clock for a restored HALF_OPEN — downtime never consumes the wait budget and a restart can never strand a trial.
- **Both HALF_OPEN exits are configurable.** `recovery.onCanaryFailure` is tri-state: `backoff` (today: ladder × `recovery.cooldownMultiplier`, capped by global `maxCooldownMs`), `initial` (re-OPEN at the first ladder rung) or `close` (optimistic CLOSED, **retaining** `consecutiveFailures` and `currentCooldownMs` so the next counted failure re-trips escalated). `close` never applies to a `MANUAL` breaker — category `MANUAL` falls back to `backoff`, because a rule must not defeat an operator takedown. Three conditions resolve through this one policy: a probe failure, `maxWaitMs` expiry (`recovery.halfOpen.maxWaitMs`, default `0` = wait forever, today's shape; checked on the next gate call), and a **short batch**: all `maxProbes` slots consumed with `halfOpenSuccesses < successThreshold`. The short-batch check is gated on `successThreshold > 1`, so the default 1/1 shape is untouched — a stuck single canary lingers as it always did instead of being re-tripped while its probe is still in flight. A short batch counts **no new failure** (nothing failed; the trial simply cannot reach the bar) and re-OPENs with `breaker.canary`.
- **Shadow mode flips the verdict only.** `circuitBreaker.shadow: true` keeps the machine running at full fidelity — probe slots consumed, ladders advanced, windows filled, trips recorded, snapshotted and emitted — while `canExecute`/`peekExecute` return `allowed: true`. The exemption is structural, not a special case: the flip lives in the breaker's verdict and refuses to apply to category `MANUAL`, while the DISABLED operator takedown and the SUSPECT refusal are answered by the manager before any verdict is consulted. Accepted observation skew: shadowed models keep serving full traffic, so statistical history diverges from an enforcing run.
- **SUSPECT is set on trip and never lifted by a toggle.** `markSuspect` rides the trip itself: an auth rule OFF is "ignore" (no trip, no count) and therefore sets **no new flag** — an ignored 401 must not administratively eject an account; gating `accountSuspect && trip.auth.enabled && trip.auth.markSuspect` is the shipped contract. `markSuspect: false` keeps the trip and stops only NEW flags; entries already in `suspect-accounts.json` keep gating selection until the operator clears them. The invariant across the whole rule tree: **a toggle neither sets nor clears an existing flag.** The mark lives on the account-expansion path, so a `scope` override that routes a 401 to a pair or model breaker trips without flagging (ADR-0019 Decision 6).
- **Apply semantics stay restart-based.** The effective ruleset is resolved at construction and snapshotted into every breaker; `handleSaveConfig` hot-applies proxy/capture/layer2/combos/tiers only, never breaker rules. Rule editing lives on the dedicated `/breaker-rules` page; `/guardrails` keeps live observation and the manual trip/reset cards with a link to it.

**Consequences.**

- (+) Each §1 taxonomy class can be tripped, counted or ignored on its own terms, with per-rule cooldowns and blast radius; the operator can now express "trust the outage detector, ignore the dead-key one" instead of accepting or disabling the whole system.
- (+) A ruleset can be validated against production traffic before it blocks anything, and its inherited values are visible in the same snapshot the gate uses.
- (+) Recovery scales with the credential matrix (multi-probe, N-of-M) while the default configuration stays byte-for-byte the old single-canary behavior.
- (−) Two vocabularies now describe one machine: the machine of §2 (edges) and the ruleset of the config page (dispositions). The mapping is one edge ↔ exactly one rule owner, and the code keeps the gate as the single decision point so the two cannot drift into different answers.
- (−) Rule changes need a restart (as `circuitBreaker.*` always did), so a reconciliation of live state is deferred to the next boot; a disabled rule's already-OPEN breaker is dropped at restore, not at save time.
- (−) `minCalls`, `successThreshold` and `maxWaitMs` add operator-controlled ways to stall recovery; the clamps bound the unsatisfiable combinations, not the slow-but-legal ones.
