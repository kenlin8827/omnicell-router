# ADR-0004: Resilience — Error Taxonomy, Breaker State Machine under a Live Rule Tree, Scoped Trips, Capability Health View, Shaping vs Breaking

## Status

Implemented — 2026-10-15 (facts-side corpus rewrite). Scope: what counts as failure, how breakers trip and recover, what survives restart, how health is *named* upward, and where rate limiting differs from breaking. Execution sequencing = ADR-0005; eviction consumption of the health view = ADR-0002.

## Decision

### 1. Seven-class error taxonomy; classifier diagnoses, manager decides

`QUOTA_EXHAUSTED | AUTHENTICATION_ERROR | RATE_LIMITED | SERVICE_UNAVAILABLE | CLIENT_ERROR | MANUAL | UNKNOWN` (`resilience/types.ts:7-15`; 5xx + network causes — reset/timeout/DNS — all fold into SERVICE_UNAVAILABLE with a `networkCause` sub-vocabulary). Status extraction tolerates numeric, message-text (`status: 429`) and provider-code-string forms; `Retry-After` supports integer seconds only (HTTP-date unsupported).

Default dispositions (each overridable by the rule tree; "under-cool, never over-cool" is the shared bias):

| Class | Trigger words/status | Default scope | Cooldown | Side effects |
| :--- | :--- | :--- | :--- | :--- |
| QUOTA | 402/`insufficient_quota`/balance wording | credential | `trip.quota.cooldownMs` (12 h floor) | never SUSPECT |
| AUTH | 401/`invalid_api_key`… | credential | `trip.auth.cooldownMs` | `markSuspect:true` |
| RATE_LIMIT | 429/503+limit wording; `Retry-After` honored | credential if credential-limit markers, else pair | `clamp(RA·1000,[1s,maxCooldown])`; no RA → `min(60s,initial)` | short burst (RA ≤ `maxRateLimitWaitMs`) in-place retriable; **long RA hard-trips at that length — trust the provider's stated wait** |
| SERVICE_UNAVAILABLE | 5xx/network | model | ladder (30 s→×2→5 h) | — |
| CLIENT_ERROR | 400/422 + wording | never trips | — | counted only when `counting.clientErrors` ON (the only inversion) |
| UNKNOWN | anything else | pair | counted statistics | — |

Scoping rule: a trip is scoped ONLY when the error carries credential attribution (stamped by `registry.execute`); unattributable errors never carry `tripScope` (absence = model). The stamp also rides on the diagnosis itself (`ErrorDiagnosis.usedKeyHashPrefix`), and the manager attributes from it when the caller's selection prefix is absent — a degenerate selection (all-unhealthy / all-disabled / no-session) still executes on the chain head, and a credential-fault error from that attempt must cool the credential that actually served it, never the model breaker. Rules' per-class `scope` overrides the diagnosis — after attribution, never before.

### 2. Three-state machine over (model × credential) tuples; scopes are fan-out writes

`CLOSED | HALF_OPEN | OPEN` (`CircuitBreakerState`) — this vocabulary belongs to the breaker component and is NEVER reused for model-level aggregation (see §4). The ONLY breaker state machines are the (model × credential) TUPLE breakers keyed `modelId::keyHashPrefix`; `keyHashPrefix === ''` is the SENTINEL tuple for the chain-less credential (a provider's config-baked key), so every legacy model-level path degenerates to exactly one tuple. There is NO model-level breaker state machine: the "model level" is a derived fold (`getAllSnapshots`/`getSnapshot`) over the model's tuples — worst state wins, kept for summary/UI compatibility.

Blast radii are fan-out WRITES over tuples, each target recording the scope label (`CircuitBreakerSnapshot.scope`):

- scope `pair` → the single tuple (provider + modelId + credential);
- scope `credential` → every tuple of (provider, credential) across the models it can reach;
- scope `model` → EVERY tuple of the modelId (equal fan-out accounting: each tuple's ladder sees the model-level failure, so one key serving a dying upstream still trips the whole model at the threshold); the orchestrator passes the full chain so keys that never served the failing attempt are covered — and the same full-chain threading applies to MANUAL model trips (the REST seam resolves the provider's chain via the registry), so an operator takedown cannot degenerate to the sentinel tuple on a model with no failure history.

Detection: per-class consecutive-failure ladders + sliding failure-rate window (defaults threshold 3/window 20/50 %; `initialCooldownMs` 30 s, ×2 escalation, `maxCooldownMs` 5 h cap; quota fixed 12 h). Recovery trial: `recovery.halfOpen.{maxProbes,successThreshold,maxWaitMs}` + `onCanaryFailure: backoff|initial|close` (MANUAL forces backoff; default threshold 1 = canary-closes-on-first-success). Trials are PER-TUPLE: after a model-scope fan-out trip each tuple needs its own `successThreshold` successes, so full-model recovery latency scales with the credential count (by design — a tuple only closes on evidence ITS key serves again). The per-model probe budget (`halfOpen.maxProbes` per prober cycle) is shared across a model's tuples, so fan-out cannot multiply background load.

- **Consuming gate** `canExecuteScoped` is called only immediately before an upstream call — it is the ONE tuple's gate (+SUSPECT); `canExecute(modelId)` is the sentinel tuple's gate (chain-less path). **Peek** `peekExecute` (selection, pool filters, leader picks, console) NEVER takes a probe slot — lookups would starve a recovering tuple into permanent HALF_OPEN.
- Credential-scope verdicts never touch the other credentials' tuples, and tuple states are the card's own truth in the console — the derived model fold is display context only, never painted onto a healthy sibling card.
- Non-penalty outcomes (rule-dropped, `shouldTripBreaker:false`) release any consumed probe slot; client-side 413/499 never reach the breaker at all (no upstream call → no record).
- **Commit point (streamed turns).** Failover and in-place retry are legal only while no byte has reached the client. Once the relay forwards a frame the turn is committed: a later upstream break is still classified and recorded through the normal taxonomy (health stays honest), but is never re-issued — a retry would hand the client a second copy of a generation it has partly consumed. The stream simply ends without `[DONE]`, which is also the signal to the client that the turn did not complete (ADR-0008 §1).

### 3. Live rule tree with contractual OFF-semantics

`circuitBreaker.rules` (global ⊕ per-provider overrides): counting/trip/recovery per class — UNSET fields fall back to the global knobs (legacy behavior = the defaults). Hot-applied on EVERY console save (`manager.applyConfig` — swaps rule sets, never live state machines; the single reconciliation: OPEN breaker whose tripping rule was disabled is released now) (`routes/console.ts:1082,1106`). OFF-semantics are contract, not implementation detail: counting-off = neither recorded nor tripped (and releases a consumed slot); trip-off quota/auth = full ignore (no trip, no count, **no SUSPECT** — an ignored 401 must not eject an credential); trip.rateLimit-off = long-RA 429 downgraded to a counted statistical failure, RA-derived floor still flows. Invariant across the tree: **a toggle neither sets nor clears an existing flag** (`markSuspect:false` stops NEW flags; existing SUSPECT keeps gating selection until manual clear). SUSPECT is set only along a trip; only reconnect/Push/admin clear it. Operator DISABLED is runtime-invisible to the classifier yet outranks every selection degeneracy (never served by force). Shadow mode: automatic trips never deny (accounting runs); MANUAL always enforces. `circuitBreaker.enabled:false` = gates always allow + records no-op; selection flags, rate limiting, and manual trips keep working exactly as configured.

### 4. Two health readings, one deliberate divergence

- `modelAvailability` (PEEK-based boolean aggregate): a prefix is out iff `isPairOut` (DISABLED first, then SUSPECT, then tuple-breaker-peek); the model is available iff at least one candidate prefix is not out. With an EMPTY chain (chain-less provider) the SENTINEL tuple is the only gate — it is consulted, so a manual model trip on a chain-less provider reads out as unavailable exactly like a chained takedown. Serves pool building, selection, the eviction **landing guard**.
- `modelHealthView` ∈ `available | recovering | unavailable` (STATE-based aggregation, non-consuming `getState()`, shadow-folded exactly like the `verdict()` contract: a shadowed automatic trip still serves so it never reads out; MANUAL stays verbatim): `available` = some tuple CLOSED (or none exist yet); `recovering` = trial in flight (canary slot free OR busy) without a CLOSED tuple; `unavailable` = every tuple hard-OPEN/DISABLED/SUSPECT with no trial in flight. Takedown outranks recovery-in-progress; chain-less providers degenerate to the sentinel tuple state. Serves the session-pin EVICTION (ADR-0002 fires only on `unavailable`) — so an operator never confuses "a canary just started" with "gone".

The divergence is the point: a busy canary reads unavailable on peek — pools route around it this turn, the peek-based landing guard refuses it, but the state view protects live bindings from being moved off a model one probe from recovery.

### 5. Breaker memory persistence — per-env state, global flags

Breaker state machines persist to `<home>/breaker-state.<env>.json` (per ENVIRONMENT book-set): full state + sliding outcome windows survive restart; HALF_OPEN restores with probe counters CLEARED and `enteredAt` re-anchored (a snapshot taken mid-canary must not starve the trial); `cooldownUntil` gets a clock-skew guard; writes are debounced (`persistence.debounceMs`, not hot-applied), atomic temp+rename 0600, corrupt files kept aside `.corrupt.<ts>`; flush on SIGINT/SIGTERM/SIGBREAK/exit. Administrative flags persist GLOBAL (`suspect-credentials.json` — suspects AND disabled entries): they attach to the credential, not the book-set. Loading skips records whose rule is permanently disabled. Only TUPLE records carry state; the legacy `models[]` layer of pre-tuple files is read-and-ignored (the model level is derived now), and the field is written as `[]` for file-shape compatibility.

### 6. Active health probing (opt-in)

`circuitBreaker.activeProbing.enabled:false` default; prober interval `activeProbing.intervalMs`. Every tick scans pairs for HALF_OPEN-or-cooldown-expired-OPEN and runs a `max_tokens:1` `health_check_ping` through the REAL execution path (credential re-stamped → scoped diagnosis). The prober never consumes traffic canary slots: it holds its own model-slot budget (= `halfOpen.maxProbes`) and picks the first not-out "representative credential" per pair; SUSPECT never self-returns; a fully-out chain skips the cycle. Probing converts passive cooldown into verified recovery, at the cost of ~zero tokens.

### 7. Rate limiting — a different axis: quota shaping, not health

Separate engine (`ratelimit/`): sliding-window log over `requests | tokens | costUsd` (any full ⇒ verdict) on a MONOTONIC timebase (`performance.now()`; window math is delta-only, so NTP steps cannot shrink/balloon a window; persistence rebases to/from wall clock at the checkpoint boundary). Two directions: **inbound enforcement** per apiKey (429 + `Retry-After` + `RateLimit-Limit/Remaining/Reset` headers, OpenAI-error body with `param=limitedBy`; the rejected request does NOT count; bounded grace-wait ≤ 2 s re-checks once before denial, with at most `MAX_GRACE_SLEEPERS` concurrent sleepers — beyond that the courtesy is shed and the denial fast-fails; MITM leg is not inbound-metered) and **outbound shaping** per credential (`credential:<provider>:<keyHashPrefix>` overlay limits: selection SKIPS at-cap credentials for new placements only — the kept-binding iron law says a bound session is never moved by a local cap, only by the provider's own 429/pair-open/takedown; the last-candidate force still serves, attributed `forced`). Token admission PRE-RESERVES a chars/4 prompt estimate in every tokens window (`tryDispatchWithEstimate`) and reconciles it against actual usage at response close (`releaseEstimate`) — a request can never slip through a token cap on usage it has not produced YET, and the reservation releases even on failed/aborted turns (one close-registered release per request, keyed on the FINAL admission verdict — the grace path re-reserves at re-check, so a first-pass registration would leak it; reservations do not age out, so a window full purely on reservations reports a 1 s `Retry-After` floor instead of an immediate-retry 0). An upstream 429 additionally feeds a subject-wide SHAPING cooldown into the engine (`penalize`, Retry-After-driven, clamped [1 s, 1 d], 60 s default without a usable header): new-session steering avoids the credential immediately instead of re-discovering the wall — the breaker keeps its own independent hard-trip cooldown and the 429 still belongs to the breaker, not the ledger. Every candidate order is fixed: select-credential → rate PEEK (non-consuming; at-cap never burns a canary) → consuming breaker gate → dispatch deduct → execute → scoped record. Event ledger kinds `denied/grace-admitted/skipped/forced/shaped`; ring 500 + coalesced WAL mirror in `traces.db` (own handle, fault-isolated, fail-open). Window DURABILITY: under `rateLimit.persist` the limiter checkpoints live window events to `traces.db` (`ratelimit_windows` table, independent handle — `window-store.ts`) every `RATE_LIMIT_CHECKPOINT_INTERVAL_MS` (30 s) and on graceful shutdown, and rehydrates them at boot rebased onto the new process's timebase — a `1d` budget survives a restart; hard kill loses at most the last interval; every store method fails open (memory-only degradation, the pre-checkpoint behavior). Live events per window are capped (`MAX_WINDOW_EVENTS`, oldest dropped → under-counts, never over-counts). Admin API: `GET /api/admin/ratelimit[/events]`, `POST /api/admin/ratelimit/events/clear`, `POST /api/admin/ratelimit/windows/reset` (per-subject, optionally per-rule window reset — no global wipe, by design).

### 8. Operator surfaces

`X-OCR-*` headers single-homed in `surfaces/ocr-headers.ts` (defaults are a frozen contract; transports decide DELIVERY, not content): chat leg 13 base (`Tier`, `Tier-Escalated`, `Layer`, `Model`, `Failover`, `Failover-Attempts`, `Failover-Path`, `InPlace-Retries`, `Breaker-State`, `Session-ID`, `Session-Ratchet`, `Session-Lookup`, `Trace-ID`, `Latency-MS`) + conditional `Thinking-Requested/Actual/Degraded` and `Variant`; decision leg exactly 3 (ADR-0008). Breaker management API: `GET /api/admin/health/circuit-breakers` (model+pair snapshots + rules banner), `POST .../reset?scope=model|credential|pair&credential=<keyHashPrefix>` (clears cooldown/failures/window/ladder — never SUSPECT), `POST .../trip` (manual, default 1 h, clamp [1 s, 7 d]), `POST /api/admin/health/suspect-credentials/clear`. Recurring misconfig warnings route through `WarnThrottle` (dedup once per process, 60 s ≤ 50 lines then fold).

## Consequences

- Hard vs soft response is class-decided, rule-tree overridable, hot-applied — with OFF-semantics specified per family instead of assumed.
- The capability/state layering of §4 gives operators one unambiguous word each for "down", "healing", and "out"; the divergence between peek and state is pinned by tests (`pin-eviction.test.ts`, `resilience*`).
- Recovery is verified (prober) or honest (peek-routed around), never accidental.
