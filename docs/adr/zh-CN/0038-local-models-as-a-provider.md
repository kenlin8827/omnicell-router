# ADR-0038 — 本地模型作为一个可路由的 provider，Strata 作为第二个运行目标

- 状态：Accepted（已实现）
- 日期：2026-11-26
- 修订：ADR-0037 §6（llama.cpp 不再是**唯一**运行目标）
- 被修订：ADR-0039（其中 Strata 专属的 profile 与运行分支收敛为统一的 `EngineRuntime` 契约）

## 背景

ADR-0037 §6 把本地运行时封在“可安装、永不服务”上：Strata 的控制面被理解为无法加载任意 GGUF，于是 `startLocalRun` 无条件回答 `engine-cannot-serve`，控制台的引擎选择器直接把它摘掉。实践中有两个事实让这条规则不成立：

- **拒绝恰好落在规则本该保护的模型上。** Strata 面向的 curated MoE 家族（`qwen3next`、`qwen3moe`、`deepseek2`、`glm4moe`、`gpt-oss`）正是运维在这里下载的东西。一条为了“只服务自家家族”而设的规则，把这些家族全部拒了，而它的文案（“Strata 只服务自家 curated MoE 家族”）在持有这类文件的人看来是自相矛盾。
- **运维本来就在跑它们。** `strata.exe --pack … --native …` 今天就能工作；那个模型是一个**构建产物**（pack 目录）加上可选的 PLE 表、MTP draft 头与 expert profile。这些没有一样能从 GGUF 头里读出来 —— 所以通用 runner 拼不出命令行，诚实的结论是“没有启动路径”，而不是“模型不受支持”。

另外，一次 run 在控制台就断头了：`startLocalRun` 给出端口和日志环，但没有任何可路由的东西。客户端只能直接指向 `127.0.0.1:<port>/v1`，等于把 OCR 的路由、捕获、协议转换与密钥纪律全部放弃——而丢弃的恰恰是运维自己在本地跑的那部分流量。

这两件事底下是同一个概念错误：把“provider”当成一个东西。它其实是两个：客户端可寻址的**命名空间**，以及一个**静态上游记录**。命名空间应该扁平且稳定；记录做不到，因为本地端点是一个每次启动都会变的端口。

## 决定

### 1. 一个 `local` provider —— endpoint 属于 MODEL，不属于 provider

`local` 是**核心自持**的 provider：由 direct-pool 构建器合成、由 `applyDirectPool` 像其他 provider 一样对账，但从不写入 `providers.json`，不进凭证链，不是配额主体，也不是同步客户端的物化目标。ADR-0010 原封不动：defs 文件仍是**运维自定义** provider 的唯一真相，而 `local` 不是其中之一。

每个已安装模型注册为 `local/<name ?? registry id>`（§7），`provider: 'local'`，`upstreamModel` = 本地服务实际应答的名字，`tier: undefined` —— 除非某个成员列表claim 它，否则不进任何池，因此本地 run 永远不会悄悄混进 `auto` 的候选集。

provider 的 `baseUrl` 是一个**永不被拨号**的哨兵值。真实的 base 在调用期按 model 解析，走的是本来就存在的接缝：`LLMProvider.dialBaseFor(model)` —— 它一直收着 model，而四个执行器里有三个把它丢了。因此本地执行器是一个**装饰器**：按 model 解析 base，为每个 base 缓存一个内部 `OpenAIChatProvider`，然后委托。不重写执行器，也不往 `ProviderConfig` 里塞函数（一个可序列化的记录必须保持可序列化）。

为什么不是“一模型一个 provider 实例”（或“一 run 一个”）？因为那样客户端契约就会编码基础设施：`local/run-8f3a`，或者一个端口。端口每次从 4800 往上分配，且按 ADR-0037 明确不是契约。`local/<model>` 是唯一能活过重启的拼写。

### 2. 单 provider 形态不能破坏的三条约束

- **熔断仍然按模型隔离。** key 是 `modelId::keyHashPrefix`（ADR-0004 的 pair 模型），所以一个 provider 行下的 N 个本地模型带 N 个独立熔断器。共用 provider 不等于共用跳闸。
- **配额整段跳过。** 该 provider 无密钥 —— 无凭证、无前缀、无探针、无 `quota_events` 行。本地算力不消耗厂商配额；为它合成一个桶等于往一个只为记录事实而存在的账本里写虚构。
- **成本是“声明的 0”，不是推导的 0。** ADR-0035 禁止在厂商未公布价格时伪造价格。本地推理的边际成本确实是 0，所以注册时明确写下 `pricing: 0`，每个成本界面读到的都是真数。真正要区分的是“已知为零”与“未知”，而这里已知。

### 3. 未运行的 run 是一个**状态**，不是连接失败

解析在**任何拨号之前**失败，返回 `local_run_inactive`，503，消息里点名模型与启动它的页面。该错误携带 `breakerExempt`，熔断器永不记录它：运维主动停止不是上游抖动，让它跳闸等于把一个刻意动作变成一个冷却期。

本地模型在**停止时仍然保持注册**。因此 id 不会在客户端配置里闪进闪出，tier 成员列表或 combo 也可以引用一个当前关着的本地模型。健康态读作 `unavailable`（ADR-0004 的词汇），也正是淘汰所依据的信号（ADR-0002）—— 一个停着的 run 不是路由候选，但它仍然是一个地址。

### 4. Strata 是真正的运行目标；它的启动输入是生成的，不是手填的

*本节最初的版本把手工填写的 profile 设为启动门槛（"pack / mtp / pleGguf / expertProfile 必填"，外加一条由网关启动的 `vision` 辅助腿）。ADR-0039 §7–§8 把两者都推翻了：工作区布局可以从模型自己的注册路径发现，`writeStrataConfig` 会在 `<home>/strata/configs/` 下生成运行配置，vision 编码器是 `server.py` 自己的子进程，profile 只作为**可选覆盖**存活——空记录是常态，`needsSetup` 永不设置。`strataFamily` 也不复存在：家族结论活在每个引擎的判定里（`engines[id].family`）。本节仍然拥有的是控制台契约：*

- **端口分配归网关所有**；profile 永不携带固定端口，因为固定端口是两次并发 run 唯一无法共享的东西。
- **主机恒为 `127.0.0.1`，不提供任何覆盖**。本地引擎是网关的**上游**，绝不是第二个对外面。已退役的 `lan` 运行选项曾允许把启动绑到 `0.0.0.0`，那等于发布出第二个 API 表面，没有路由、没有级联、没有配额、没有断路器、没有捕获、没有协议转换——而这些恰恰是运行网关的意义所在；它还换不来任何东西，因为网关反正始终拨回环（`localBaseFor`）。诊断引擎属于控制台自带的接口测试，不是一条旁路监听。因此控制台只把回环端点当调试信息展示，对外调用者被指向网关身份（`local/<name ?? installedId>`，§7）。本地模型没有任何东西依赖 `host` 以别的值抵达 `EngineLegFacts`。回环在出站策略里永远直连（ADR-0018），本地腿绝不经过代理。
- **一个参数抽屉，不做镜像**。已经是运行选项的旋钮，绝不在 profile 表单里再放一份——同一个值有两个控件，控制台就会开始谎报自己启动了什么：上下文归页面的上下文阶梯，KV 精度归加速面板（llama.cpp 的 `kvCacheQ8`）或引擎 profile 覆盖（Strata 生成的 `--kv`），额外参数归抽屉的「额外参数」字段。抽屉由引擎的 `EngineProfileSpec` 数据驱动渲染（ADR-0039）——控制台不点名任何引擎、任何字段。

**「运行」只做跳转，启动是一次显式点击（2026-11-26，2026-12 修订）。** 已装模型页的「运行」按钮链接到 `/local-run?model=<id>`——它预选好模型就到此为止。真正的启动是运行页的「启动」按钮：到达页面绝不自动拉起进程，因为加载权重代价大、占用显存，而且未必是操作者此刻要做的事（他可能先看分层方案或调一个旋钮）。自动参数集仍是页面的**默认值**（gateway 规划的引擎用规划器的自动 ctx/层切分，Strata 用生成的配置），因此「默认全自动、之后可手调」仍是同一个界面——`autostart` URL 标记及其一次性消费逻辑已退役。

**就绪的 run 展示的是网关，不是引擎。** 就绪块首先展示模型的网关 id（`local/<name ?? installedId>`，§7）、网关 base URL 和一段可复制的 cURL 快速调用——注册随每次 pool 重建生效（§1），run 一报 ready 这个 id 就可调用，路由、捕获、协议转换全部生效。引擎原始端口降级为一行调试信息：把客户端指向 `127.0.0.1:<port>/v1` 正是本 ADR 要消灭的绕过用法。

### 5. 规划器不规划 Strata

Strata 没有 `-ngl`。分层由 `--expert-cache auto` 拥有，运维的杠杆是 `--max-context`、`--kv` 与 `--pool-workers`。因此一次 Strata 启动**绕过** `planPlacement` / `nglForPlan`：run 记录里的 `ngl` 保持 `-1`（不适用），控制台展示声明的 profile 而不是分层条。

这遵循 ADR-0037 自己的规则 —— *运维读到的计划就是启动配置，两者不一致按定义是 bug*。一个 Strata“计划”会是对引擎内部决策的估算，于是根本没有可被违背的预览，控制台必须如实说明，而不是画出它无法兑现的条。

### 6. 一条刷新路径

本地注册走既有的 `buildDirectPool` → `applyDirectPool` 对账。provider-def 保存、目录自动拉取、模型安装与 run 启动全部落到**同一个**构建器，所以不存在第二个需要同步的注册面，也不会出现“配置保存后本地模型变陈旧”这类 bug。

### 7. 运维自定义名称（2026-11-26）

注册记录可以携带一个可选的 `name`：一个运维自选的短标识（`MODEL_NAME_RE` —— 1–64 个字符，限字母、数字、`.`、`_`、`-`，以字母或数字开头），在注册表内大小写不敏感地唯一。这个名字**只是**网关侧的别名：

- **注册键永远不动。** `installed.json` 仍以 `<repo>/<filename>` 为键；run、profile、构建任务与磁盘上的文件都锚在它上面。改名只动记录上的一个字段。
- **注册 id 跟随名字。** `localModelId(record)` 在有名字时是 `local/<name>`，否则是 `local/<repo>/<filename>`。反向解析（`installedIdFromLocal`）**先**把运维名字与注册表匹配，再回退到字面切片 —— 因此 `local/<name>` 能路由到记录，而未命名记录的原拼写继续有效。
- **引擎以这个名字应答。** served 别名随启动 facts 传递（`servedName`）：llama.cpp 得到 `--alias <name>`，Strata 生成的配置写入 `model_name: <name>`，于是网关发给上游的 `model` 与服务自我通告的名字一致。`servedNameFor` 先读运维名字，再读引擎 profile 的拼写，最后才是文件词干。
- **改名是显式动作，绝不悄悄改写。** 改名路由会扫描配置中对**旧**网关 id 的引用（tier 成员与排除、combo、API 密钥的 modelAccess、classifier 与默认模型设置），以 `references[]` 返回；由运维决定如何改写，绝不在原地静默修补 —— 因为一条被静默改向的 tier 成员，正是 §1 所要防止的“路由悄悄做了决定”。
- **pool 刷新走 §6**：改名通过同一条 `buildDirectPool` 路径重建注册，`/v1/models` 立即展示新 id。

## 后果

- 客户端配置一次 `local/<model>`，跨重启、端口变化与引擎切换都不必改。
- 控制台的 Local Models 页成为服务生命周期的唯一管理面，而 OCR 的常规界面 —— 路由、捕获、协议转换、密钥纪律 —— 原样作用于那部分流量。
- `engine-cannot-serve` 现在会点名缺失项：没有 profile、家族不符、或引擎未安装；泛化的“无法服务此文件”留给约束确实关于文件的引擎。
- 停止的模型仍出现在 `/v1/models`，健康态 `unavailable`。这是刻意的：一个会带着解释返回 503 的已公布 id，比一个会消失、并悄悄改变 `auto` 可达范围的 id 更好相处。
- 以后加第三个引擎只需要一个新的启动规格，而不是一个新的 provider：provider/endpoint 的拆分正是让那成为局部改动的东西。
