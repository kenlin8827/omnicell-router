# ADR-0036 — 插件引擎版本机制：一个整数，一个被拒绝的插件包

- Status: Accepted (implemented)，修正案 1 —— 引擎版本即契约版本
- Date: 2026-11-24
- 修正: 2026-11-27 —— `engines` 语义化窗口被**移除**，见下方"修正案 1"。本文档的背景、控制台/安装/加载的后果，以及每一处用户可见行为仍然有效；原决策的第 1–3 节被取代。

## 背景

`apiVersion` 原本只回答一个问题：*这个插件包是按哪一版插件契约写的？* 在本文档之前，它是一道**严格相等**的闸门——`apiVersion !== SUPPORTED_PLUGIN_API` 即在安装与加载时拒绝。这是**悬崖**而不是声明，两个代价都由运维方承担：

- **拒绝是不可诊断的。** 被拒绝的包只在加载时抛出一句话，磁盘上不留别的痕迹：升级之后运维看到的是"集成消失了"，控制台里没有任何一行说明是哪个包被拒、该怎么做。
- **反方向同样是静默的。** 清单里没有任何字段说明一个包是**针对哪一版引擎**构建的，因此也无法在它导入失败之前提醒运维"这个包在这里跑不起来"。

本文档的第一版用"给引擎一个语义化版本号（`PLUGIN_ENGINE_VERSION = '1.0.0'`）+ 让每个包在独立的 `engines: { plugin: '^1' }` 映射里声明语义化**窗口**，由内核解析比对"来回答这两点。修正案 1 移除了窗口；它引入的拒绝机制全部保留。

## 决策

### 1. 引擎版本就是插件契约版本

`PLUGIN_ENGINE_VERSION`（`backend/src/plugins/manifest.ts`）是**一个整数**，并且与 `SUPPORTED_PLUGIN_API` 是同一个数字——由构造保证（`SUPPORTED_PLUGIN_API = PLUGIN_ENGINE_VERSION`），不是巧合。

独立的引擎发版号只可能靠两种方式携带信息，而两种都经不起推敲：

- **这次发版没有改变插件面。** 那么对一个包而言它就不是另一个引擎，包声明它等于什么都没说。
- **这次发版改变了包能察觉的东西。** 那么按定义它就是一次契约变更，而 `apiVersion` 正是已经声明这件事的字段。`createPlugin(host)` 没有第二个维度可供包去依赖。

因此语义化的 minor/patch 只能靠作者**手动收窄自己的窗口**（`>=1.4.0`）才起作用，而那正是作者在断言一个网关无法核实的兼容性。整数把这个事实只说一次。

**升版纪律。** 插件面变更唯一需要的动作就是提高 `PLUGIN_ENGINE_VERSION`：声明旧值的包随即被拒绝，拒绝语指明**哪一侧**落后。内核中没有任何其他地方读这个常量——没有窗口要重算，没有下界表，没有上界。

### 2. 包在 `apiVersion` 里声明引擎，没有第二个字段

```json
{
  "id": "qoder-models",
  "version": "0.5.0",
  "apiVersion": 1
}
```

`apiVersion` 是正整数，且必须落在 `[MIN_SUPPORTED_PLUGIN_API, SUPPORTED_PLUGIN_API]` 内。

本文档第一版引入的 `engines: { plugin: <语义化窗口> }` 映射**已被移除**。它唯一能做到的事，就是用第二套词汇重述上面那个整数——一个事实两个真相，而本仓库按名字禁止这种事（AGENTS.md"单一来源常量——不做漂移副本"）。仍然带着这个键的包**不会**因此被拒绝：该键就是不被读取，与任何未知清单键一样，因为拒绝它会让包为一个曾经必须的字段而失效。

`MIN_SUPPORTED_PLUGIN_API` 从下方界定契约——今天等于 `SUPPORTED_PLUGIN_API`（只有一个契约，没有遗留），日后上调即按拒绝"过新"契约的同一方式退役 `[MIN, SUPPORTED)` 里的老契约。

### 3. 一道闸门、两个方向、各一句话

`pluginEngineCompatibility()` 是这条规则**唯一**的读取点（加载器、安装器、控制台都经由 `pluginEngineRefusal` 到达它）：

1. `apiVersion` **高于** `SUPPORTED_PLUGIN_API` —— 包是针对本构建不存在的插件面写的。`contract-too-new`。解药是更新**网关**；重装同一个文件毫无作用。
2. `apiVersion` **低于** `MIN_SUPPORTED_PLUGIN_API` —— 它针对的契约已退役。`contract-too-old`。解药是安装该包的更新版本。

其余情况都能加载。没有第三道闸门，没有窗口，没有下界，没有上界。两句话都由**内核**产出（`pluginEngineRefusal`），绝不由插件包产出：它们是关于运维必须做什么的指令，并且必须指明该动哪一侧。

语法也不再需要 fail-open 的例外，而这本身就是收益的一部分：本该是整数的地方写了字符串，两侧在同一刻被 `validatePluginManifest` 拒绝——打包侧（`plugins/pack.ts` 的 `bundlePluginDir` 会校验它即将发出的清单，因为 `collectPluginAssets` 是原样复制 `plugin.json`，除此之外没有任何环节能在运维拿到包之前拦住一个非法声明）与加载侧（无法读取的清单按失败行处理，一贯如此）。

### 4. 加载：被拒绝的包是一行"已禁用"，不是崩溃

闸门在**导入之前**（以及 `ensureUnpacked` 之前）**且早于"已禁用"台账的检查**运行，因此被拒绝的代码永不进入模块缓存、不会留下解包目录，而且一个既不可兼容、又被关掉的包，仍然会报告那个"开关修不好"的原因。这一行（`incompatibleView`）是：

- `disabled: true`、`loaded: false`、`incompatible: true`、`error` = 内核句子；
- 没有 `wires`、没有 preset、不承载任何流量；
- **不写**入禁用台账——写进去会比不匹配状态活得更久，把已经恢复兼容的包继续关着；
- 每次加载都按磁盘上的清单重新判定，因此升级任一侧后无需运维操作即自动清除。

包仍然**占着**它的 id：同 id 的低优先级副本不得悄悄在旁边加载。`loadInstalledPlugins()` 仍然只返回**加载成功**的部分（契约不变）；被拒绝的行追加进 `lastViews`，也就是 `listInstalledPlugins()` 与控制台看到的内容。

### 5. 安装：字节留在磁盘上

`installPluginPackage` 在动磁盘之前就拒绝不可兼容的包（什么都没写入，没有半装状态），以 400 携带内核句子作答。当拒绝仍然出现时——例如文件已存在、网关在其下被降级——安装路由把它与任何普通行同等对待：包留在磁盘上、列为已禁用，响应携带插件列表以便控制台立即展示。

这是与"加载失败"包的刻意区别：失败包会被丢弃（并回滚到上一版本），因为每次启动都失败对谁都没好处。而拒绝只是一个等待另一侧跟上的普通安装，丢弃它只会让运维在升级后重新上传同一个文件。

### 6. 控制台指出该升级哪一侧

`PluginView.incompatible` 是这一状态的 API 契约（前端镜像为 `PluginViewInfo.incompatible`）。插件页将它渲染为 `Incompatible` 徽章，显示指向动作的本地化提示，并隐藏禁用/启用开关——该开关只改台账，而拒绝来自加载器。卸载与设置仍然可达：被拒绝的包依旧是运维的文件，其 schema 在不导入代码的前提下也能读取。

## 修正案 1 —— 窗口已移除（2026-11-27）

上述第 1–3 节最初规定的是：语义化的 `PLUGIN_ENGINE_VERSION`，加上由 `parseWindow` 解析的 `engines.plugin` 窗口（`^`/`~`/`>`/`<`/`||`/连字符区间），并对未声明任何窗口的包缺省为 `^apiVersion`。

移除的理由：

- **它与 `apiVersion` 重复。** 一个引擎版本恰好实现一个契约，所以窗口最多只是那个整数换了个马甲。读者无法判断哪个字段是权威的，也没有任何规则保证两者一致。
- **那套高级语法买不到任何东西。** `>` 与 `>=`、上界、`~` 与 `^`、`||` 并集、连字符区间，全部由测试覆盖，却没有任何生产清单使用：所有随附的包都声明 `^1`，也就是契约整数。只有测试能看见的复杂度不是特性。
- **它的逃生门在两个方向上都是假的。** 解析失败的窗口必须在加载时被容忍（"没有意见"，以免手改文件把安装弄废），这意味着一个笔误就能发出一个声称了从未声明的兼容性的包——而堵这个洞需要新增一道打包闸门，而那道闸门存在的唯一理由就是看管一套没人需要的语法。

原样保留的：两个方向的拒绝与两句不同的话、那一行的形状（`incompatible`、`wires: []`、不写台账）、闸门早于禁用判定、闸门早于 `ensureUnpacked`、安装时动盘前拒绝，以及控制台徽章。它们才是目的；窗口只是载体。

**兼容性说明。** 没有任何随附的包需要改动才能继续加载：7 个包全部声明 `apiVersion: 1`，被移除的 `engines` 键是被忽略而非被拒绝。没有迁移步骤，也没有 schema 版本升级。

## 后果

- 插件面变更现在只需一次编辑——提高那个整数——其效果在下次加载时对所有已安装的包可见。
- 下一次引擎升版是一次真实、公开的破坏：所有声明旧契约的包都会停止加载，且以运维看得见、能处理的方式停止。
- 被拒绝的包永不静默。旧行为（抛一句、然后列表里没有它）已移除。
- 一个包针对什么，只有**一处**声明；也只有**一个**读取点——这正是窗口给不了的属性。
