# ADR-0029 —— 包的生命周期：随包、升级、拒绝

- **状态：** 已实现
- **日期：** 2026-11-15
- **关联：** [ADR-0017](./0017-client-gateway-plugins.md)（插件契约）、[ADR-0027](./0027-client-adapter-plugins.md)（client-adapter 包）、[ADR-0028](./0028-multi-part-plugins.md)（多 part 包）

## 背景

插件包从“一台机器上只有一个的实验件”变成“产品功能的交付形式”之后，三个缺口立刻暴露：

1. **应用自有层从来没有被填过。** `<ocrHome>/plugins/bundled/` 的语义早就定好了（优先于操作者安装、卸载写墓碑而不是删文件），但构建流程只写 `.plugin-dist/`。于是每一个离开核心、下沉到插件的 hook（`opencode-gateway` 是第一个，见 ADR-0027 / ADR-0028）在全新安装里都不存在，要操作者手工上传 zip。“作为插件发布”实际上等于“什么都不发布”。
2. **安装没有版本策略。** 任何声称同一 id 的 zip 都会替换现有包。一个过期的下载可以把已经修好的安装静默回退，唯一的痕迹是控制台那一列版本号。
3. **被改名的 client id 会复活。** `opencode-proxy` 在它的包合并之后不再是内置 hook（`opencode-gateway`）。操作者机器上残留的旧包用这个退役 id 注册成功，于是同一个客户端出现**两行** Client Hub——两份 sidecar、两个写同一批 env 的写者，谁后跑谁生效。没有任何地方报出这个冲突，因为没有任何地方认为它是冲突。

还有一个更小的：`importPlugin` 先 stage 网关、后注册适配器。注册失败的包，网关照样被提交——控制台那行写着 error，网关却还在拦这个客户端的流量。

## 决策

### 1. 应用自己播种自有层

`seedBundledPlugins()` 在每次插件宿主重建的开头（启动、安装、启用/禁用），把 `.plugin-dist/*.zip` 复制进 `<ocrHome>/plugins/bundled/`。桌面端由启动器显式指定来源（`OCR_BUNDLED_PLUGIN_SRC = <资源目录>/plugins`，打包器把 `.plugin-dist` 放在那里）；没有该变量时使用仓库内的 `.plugin-dist`，从模块自身位置解析，因此源码树与编译产物树一致。

规则：

- **字节即版本。** 完全相同的文件不动——重写会改变 mtime，而 mtime 正是 `ensureUnpacked` 判断是否需要重新解压的键，随手的播种会让每次启动都重解压所有包。
- **同一 id 在该层只留一份。** 制品改名后删掉声称同一 id 的旧文件：发现顺序按**文件名**排序，残留的那份会偶然胜出或偶然落败。
- **校验不过的包不播种。** 写了一半的构建产物一旦成为应用自有包，就会遮蔽一个能用的操作者安装。
- **开发树禁用播种。** `OCR_PLUGIN_SRC_DIR` 意味着操作者正在改源码；把过期的 `.plugin-dist` 提升到正在编辑的树上，是唯一绝不能发生的结果。
- **墓碑不动。** `disabled.json` 是操作者的账本，重新播种的包在他发话之前一直保持禁用。

### 2. 升级是更高版本；降级是拒绝

`installPluginPackage` 会把上传清单的版本与磁盘上已有的包比较（打包形态见 ADR-0017 §6，版本比较用 `utils/semver.ts`）：

- 更高 → 升级：替换包，`<pluginsRoot>/config/<id>.json` 原样保留，解包树重新解压；
- 相同 → 重装：允许（这正是替换一个坏构建的方式）；
- 更低 → **拒绝**，消息里点名已安装的版本，并把“先卸载”作为出路。

拒绝本身就是重点：控制台的上传按钮分不清“手滑”和“有意回退”，所以有意的那一次必须显式。唯一允许降级的内部调用者是安装**路由**的回滚路径——包装载失败后把旧字节装回去，它显式传 `allowDowngrade`，因为那次替换从来不是操作者要的。

### 3. 退役的 client id 是拒绝，不是别名

`RETIRED_CLIENT_IDS` 把曾经内置的 hook id 映射到它的替代者（`opencode-proxy` → `opencode-gateway`）。`registerPluginClientAdapter` 拒绝这样的 id，于是残留的包装载失败，**以错误的形式显示在它自己的控制台行上**，消息里带着替代者的名字。

这里没有别名层，而且是有意的。别名会让一个不兼容的包看起来“装了、能用”，这比看得见的失败更糟：操作者会对同一个客户端看到两行，而且任何地方都不会告诉他该留哪一行。不兼容是控制台**能显示**的状态，把它藏起来才是真正的错误。

### 4. 注册失败即关闭

- 适配器 part 在网关 stage **之前**注册。它才是能拒绝一个包的那一半（内置 / 退役 / 重复 client id），所以拒绝必须发生在任何流量归属存在之前。
- 提交点只保留那些产出了**已装载**行的 id 的网关。一个在拦流量、却没有行可以禁用的网关是不可达状态——操作者唯一的补救办法是手工改文件。
- 插件贡献的客户端 hook 走同一个事务：注册先写进 staging 映射，适配器集合在这个提交点整体交换，因此中途抛出的重建会保留**上一套** hook。绝不能出现的半状态是：Client Hub 空白，代理腿却仍在拦截。
- manifest 可读时，失败行保留它的名称、版本和声明的扩展轴。“这是哪种插件、哪个版本”正是操作者识别一个坏包时最先要看的东西。

## 后果

- 全新安装第一次启动就有随包插件，应用升级原地替换；操作者不必为了一个随产品发布的功能去上传 zip。
- 随包插件按定义属于应用：上传路由拒绝遮蔽它们（ADR-0017 §6），所以它们的升级随版本发布而来，而不是随上传。操作者安装仍然留给第三方包。
- 启动现在会**写** `<ocrHome>/plugins/bundled/`。它是幂等的、按字节比较的，但它确实是写：只读的 OCR home 会让播种变成空操作、该层为空，与本 ADR 之前的状态相同。
- 包不再对改名的 client id 静默向前兼容。旧包大声失败，操作者删掉它、装上替代者。控制台就是迁移界面——没有自动迁移，这是故意的。
- `config/<id>.json` 仍然跨版本存活，因此被新版本改名的字段不再生效（由新默认值接管），而旧键留在文件里。按版本迁移的钩子仍未实现；在那之前，改名是一次要在发布说明里声明的破坏性变更，而不是宿主去猜的事。
