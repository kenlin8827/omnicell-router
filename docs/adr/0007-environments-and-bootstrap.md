# ADR-0007: Environments — Book-Set Directories, Controlled-Restart Switching, Redacted Export / Guarded Import

## Status

Implemented — 2026-10-15 (facts-side corpus rewrite). Scope: what an "environment" is on disk, how one is chosen, switched, exported, imported, deleted. Credential storage is global-leaning by contrast (ADR-0006 §1/§6); breaker memory is per-env (ADR-0004 §5) — both are deliberate splits documented there.

## Decision

### 1. One layout, no mode branch

Every environment is a directory: `<home>/envs/<name>/` containing `config.yaml · data/ · models/ · catalog/ · traces/ · capture/ · webauth-secret · env.json` (`config/env.ts:241-255`). `<home>` = `~/.omnicell-router`, overridden wholesale by `OCR_HOME` — the single sandbox lever (the isolated test runner gives every test file its own `OCR_HOME` + `OCR_ENV=itest`; the name deliberately avoids the bootstrap tier so a leaked sandbox fails fast at boot instead of silently writing the operator's real `default` book-set). The DESKTOP app runs the same engine under its own home (`%LOCALAPPDATA%\omnicell-router` on Windows) and, when it
registers the `ocr` command, pins that home INTO the generated shim: a shim leaving `OCR_HOME` unset would read
`~/.omnicell-router` and report "not running" for the gateway the app is serving. One home per install, whichever
entry point is used. Process-level files (`ocr.pid`, `ocr.log`, `ocr.info.json`) live at `<home>` root, belong to no env; `info.json` records the active env name. `default` is the BOOTSTRAP tier: always resolvable, created by scaffold at first boot, never creatable/renamable/trashable by hand. `env.json` = schema-v1 meta `{name, type, createdAt, schemaVersion, description?, importedFrom?}`; name syntax `^[a-z0-9][a-z0-9_-]{0,31}$`, case-insensitive dedup.

Legacy layout support is REMOVED, not shimmed: no `legacyConfigPath()`, no mode branch — the pre-environments locations (repo-root `config.yaml`/`data`/`models`, `<home>/{catalog,traces,capture,webauth-secret}`) are read by NO code path; a machine upgrading starts from scaffolded defaults and copies old files by hand if it wants them. No migration tool ships. `ensureEnvScaffold` creates directories ONLY — the commented `config.yaml` template is the config layer's job, and `createEnv` templates are `blank | copy-current | copy-default` (config only; data never copied).

### 2. Resolution: OCR_ENV > pointer > default — and customPath is NOT a lever

Selection priority: `OCR_ENV` env var (fail-fast: a named env that does not exist = boot error, never silent fallback) → `envs/current` pointer file (atomic tmp+rename; CORRUPT pointer is the single forgiving limb: fall back to default with one warn per process) → `default`. `customPath` is merely the explicit config-FILE argument (`getConfigPath(customPath?)`, CLI `--config`, tests) that overrides the selected env's `config.yaml` path — it never selects an environment. Resolution is cached at module level per process (`resolveEnvName` strict / `peekEnvName` forgiving for badges) — the import-time-singleton reality that forces switching to be restart-based (ADR-0005's boot-scoped pool is the same root cause).

### 3. Switching = controlled restart handoff; hot swap rejected

Hot-swapping environments in-process is rejected on documented grounds: WAL'd SQLite handles (traces.db shared + finops + ratelimit each opened per-env at boot), module-level path singletons, Windows file locks on running dirs. The console `POST /api/admin/environments/:name/switch` is the ONLY restart-side path (CLI `ocr env use` just writes the pointer for the next boot). Switch sequence: 404 guard → target already running? pin pointer only, no restart → single-in-flight guard → write pointer ("switch to default" writes the literal `"default"`, never deletes the pointer) → spawn a detached restart SUPERVISOR (`OCR_RESTART_SUPERVISOR=1`, `OCR_RESTART_OF=<parent pid>`) → parent exits after 500 ms. The supervisor never serves: it waits for the parent's death (15 s force-kill), lets the listen socket release, spawns the replacement gateway DETACHED with `OCR_RESTART_SELF_REGISTER=1` (the gateway writes the pid/info files once listening), and polls `/health` for up to 40 s. A replacement that EXITS is retried (3 attempts, 1 s apart); a live-but-silent one owns the port and is left alone as `unverified` (it may still finish booting — spawning a second copy would only fight it). Every spawn STRIPS the inherited restart role flags first (env object on POSIX, inline `set "NAME="` on Windows — object deletion alone does not reach the native Windows child block), else a gateway child re-enters supervisor mode and a supervisor waits on a stale pid. Supervisor diagnostics go to `<home>/ocr.restart.log`, NEVER the gateway's `ocr.log`: on Windows the supervisor's own `cmd >>` handle keeps the file open, so the replacement's `>> ocr.log` fails to open and its cmd exits silently — that same-log collision is why the pre-supervisor Windows UI restart never came back. The verdict lands in `<home>/ocr.restart.json`, which `ocr status` surfaces: a failed handover has no HTTP surface left to report through, and being detached means closing the caller/terminal/desktop window cannot kill the handover mid-flight. `ocr start` spends the SAME 40 s health budget before it answers and writes the same verdict (`ok`/`unverified` instead of a blind spawn success). A handover cancelled by `ocr stop` records a `failed` verdict, and the replacement it had already spawned is published in `<home>/ocr.restart.child` the moment it exists: the killer targets the tracked pid, so on Windows `taskkill /F` delivers no cancel signal, and that record is what keeps an orphan from binding the port after `ocr.pid` was unlinked. The console Restart button uses the SAME supervisor with PORT/HOST pinned; PORT/HOST discipline distinguishes the two spawn kinds — plain restart PINS the current PORT/HOST; env-switch NEITHER pins nor inherits them — the target env's own `config.yaml` decides (an inherited `HOST=0.0.0.0` would force webAuth on a child whose parent already exited = whole-gateway outage). Spawn failure rolls the pointer back and the parent keeps serving; a supervisor that exhausts its attempts leaves the pointer on the target env and the failure verdict in `ocr.restart.json` (no process is left to roll it back — the operator retries with `ocr start`). When the target env's config port differs, the response carries `newPort` (clamped 1-65535) and the frontend follows the redirect. **Host context differs, the engine does not**: a browser console's origin is the gateway, so it polls `/health`, waits for the redirect and toasts a timeout; the DESKTOP shell's webview is a REMOTE page over the sidecar's HTTP origin (no Tauri IPC there), so the SHELL owns recovery — it polls `/health`, swaps the webview to the boot splash after 2 s down, follows `ocr.info.json` to the (possibly new) port when health returns, and shows the `failed` verdict + log path in a native dialog instead of a toast a dead origin cannot deliver. RUNNING env rename/replace/delete/reset are refused (Windows file locks, honest reason).

### 4. Per-env web-auth secret

Session cookie = HMAC-SHA256-signed `ocr_session` (HttpOnly, SameSite=Lax); the signing secret lives in the ACTIVE env's `webauth-secret` file — created `randomBytes(32)` hex 0600 on first use, survives restarts (the Restart button must not log the operator out), and per-env secrecy means one env's cookie cannot be replayed as valid in another. Unreadable secret ⇒ in-process ephemeral fallback (never boot failure). Non-loopback binding still FORCES webAuth at boot (`validateWebAuthStartup`).

### 5. Export — explicit 'ocr-env' envelope, redact-by-default

Container: format id `'ocr-env'` version 1, transported as a `.orc_env.zip` (`<name>-YYYYMMDD.orc_env.zip`) — its OWN envelope (manifest + config.yaml + payload entries), NOT an opencode-compatible file, and explicitly NOT the abandoned custom `OCRENC1` container. Payload set is CLOSED: the EXPORT set is two keys — `data/layer2-decisions.jsonl`, `catalog/overrides.json` — and `catalog/ocr.json` is deliberately excluded (signature-keyed, rebuildable). The IMPORT whitelist EQUALS the export set: an envelope carrying anything else — including the retired `catalog/custom.json` (ADR-0010 unification amendment) — is REFUSED outright (`Unsupported payload key`); the old pass-through path (checksum enforced, entry dropped, never written back) is gone, so pre-amendment book-sets are no longer silently healed — the operator re-exports from a live instance instead. Secret policy: `webAuth.passwordHash` stripped ALWAYS; session secret / CA material / traces / capture / logs NEVER included; credential-bearing values in config.yaml redacted by default (`__REDACTED__` sentinel + `redactedPaths` list; type-agnostic — any non-empty scalar at `adminApiKey`, `apiKeys[*].key`, userinfo-bearing `proxy.url`, `opencode.password`); plaintext keys opt-in `?secrets=include` only. `?include=` selects a payload subset (unknown keys ignored — the closed set is the contract). `?encrypt=1` ⇒ standard zip + WinZip AE-2 AES-256 entries (zip.js, PBKDF2-HMAC-SHA1 pinned to the WinZip 1000 iterations, CRC-32 stored 0, manifest sha256 stays the integrity layer; password via `x-ocr-archive-password` header — NEVER a query parameter; `encrypt=1` implies `secrets=include` since the layer carries the protection; third-party unzip with the password alone works; offline decrypt script ships).

### 6. Import — default-new, replace-via-trash, guard stack

`POST /api/admin/environments/import` — zip bytes only (Content-Type untrusted), body ≤ 64 MB. Guard stack, all enforced: entry whitelist (hostile names like `../escape.txt` are LISTABLE but never extracted); zip-bomb check from the central directory BEFORE extraction (single 32 MB / total 128 MB); path traversal double-checked (validation + re-`safeResolveWithin` at the write point); the payload whitelist outranks traversal-safety (payload keys `config.yaml/env.json/webauth-secret` refused — they would smuggle un-sanctioned content past redaction); envelope version gate (newer than this build = "upgrade OCR"); checksum REQUIRED and byte-exact (redaction happens after verification); `__REDACTED__` sentinel recursion-stripped and `__proto__/constructor/prototype` keys dropped on config rehydration; WRONG PASSWORD IS INDISTINGUISHABLE FROM CORRUPT BYTES (single 400 — no decryption oracle); `?name=` re-targets the import through the same syntax/reserved checks. Semantics: `mode=create` (default) NEVER overwrites (409 + `suggestion: <name>-imported`); `mode=replace` moves the old book-set to `envs/.trash` FIRST (recoverable, same mechanism as delete), then writes — RUNNING target refused; `default` is replaceable exactly via this trash→scaffold→archive route (deliberate recovery path). Partial-write failure trashes the half-built env.

### 7. Delete and sandbox

Delete = confirm-gated MOVE, never rm: `envs/.trash/<name>-<timestamp>` (pointer pointing at the deleted env cleared atomically); `default` protected; RUNNING refused. `EnvType = regular | sandbox`; `POST /:name/reset` exists ONLY for sandbox envs — wipes `data/ traces/ capture/`, keeps `config.yaml + env.json`; regular envs are never silently cleared (CLI `ocr env create --sandbox`, `ocr env reset` refuses a RUNNING env via daemon info). Nine routes under `/api/admin/environments` (list w/ current+running+sizeBytes, current, create, import, PATCH rename/description, delete, reset, export, switch); `switch` is the only route with restart side effects (spawn/exit injectable for tests).

## Consequences

- "An environment" is a foldable directory: copy the dir, or ship it through the redacted envelope — state boundaries are visible from the layout itself.
- Switch semantics match the runtime's real constraint (boot-scoped singletons), and the failure modes (rolled-back pointer, no-port-inheritance child, newPort redirect, failed/unverified handover verdict) are specified, not improvised.
- A restart that dies leaves a durable verdict: the detached supervisor writes `<home>/ocr.restart.json` and `ocr status` reads it, because a gateway that never came up cannot report over HTTP. Detachment is what makes the handover survive the caller's exit; supervision is what makes "restarted" an observed fact, not a spawn return value.
- Tests: `env-resolution`, `env-archive` (incl. encrypt/import guards), `environments-api`, `env-file-immunity`.
