# ADR-0005: Execution Topology — Pure Direct Execution, the Single Candidate Choke Point, Two-Stage Retry, Cache Economics

## Status

Implemented — 2026-10-15 (facts-side corpus rewrite). Scope: how a decision becomes an upstream call; what the boot pool is built from; retry/failover semantics; streaming; token-saver compression; cost truth. Health semantics = ADR-0004; addressing/membership = ADR-0003; credential selection/affinity = ADR-0002. Amended 2026-10-21: the hand-written `config.yaml` `providers[]` surface is retired — chat providers come exclusively from the defs file + CredentialStore (ADR-0010); the native System One upstream limb (`systemoneUpstreams[]`, vendor passthrough) is retired entirely (ADR-0008 amendment) — the decision surface serves conversion-only; a `buildDirectPool` failure no longer falls back to config-defined providers (registry boots mock-only). Amended 2026-10-22: the native limb is REINSTATED as a def-driven wire (ADR-0008 §7) — models whose resolved wire is `systemone` (defs `npm '@ai-sdk/typesafe-ai'`) are served by vendor passthrough (`protocols/systemone/native.ts`); `systemoneUpstreams[]` stays retired.
- **Amended 2026-12**: explicit-model failover is retired — a named model serves or errors; the execution chain no longer appends the tier pool behind it (ADR-0014 amendment; per-request `router_options.failover` opt-in).

## Decision

### 1. Pure direct execution — no daemon on the inference path

The gateway calls provider HTTP endpoints itself; nothing on the request path depends on any background helper process (the historical "daemon" was fully removed from inference; the name `bootDirect` is the surviving evidence). `buildDirectPool` runs at BOOT ONLY (`index.ts:124`; no pool-rebuild HTTP endpoint exists — provider defs and credentials are boot-scoped, tier membership is live per ADR-0003). Mock mode injects `mock-lite/plus/pro/ultra` only when the pool is empty (`registry.ts:115-152`).

### 2. Three sources of truth for the boot pool

`providers/boot-direct.ts`: (a) the OCR provider-defs file's provider nodes (`<ocrHome>/providers.json`; ADR-0010 — the former `opencode.jsonc` read: same node shape, same parser, one-shot ported at boot; legacy node-level `npm/options` shapes are dropped-and-reported; `env:[VAR]` names materialize to `{env:X}` templates). The node's `models` map IS the provider's universe: an empty node routes nothing (the catalog is a SOURCE for the node, never a fallback pool; ADR-0010 amendment); (b) the boot-bound CredentialStore chain (ADR-0006) — `resolveKey/resolveKeyChain` with the first-slot invariant: `chain[0].key === config.apiKey`, inline keys unshift ahead of store keys, raw keys stay IN-PROCESS, never serialized; (c) the catalog (wire + pricing + capability metadata for the maintained ids, ADR-0007 domain boundary: catalog files, this record consumes).

Failure doctrine: an unroutable provider is EXCLUDED and reported (`db_unreadable | no_credential | no_baseURL | all models unroutable`), never a boot abort; OAuth rows are listed-and-badged, never enter chains, never routed (`:163-209,323-326`). Wire dispatch is DATA-DRIVEN: npm package priority `model > catalog entry > provider def > recommendation` — protocol truth lives in catalog data, not code tables (`wire.ts:1-11`); per-provider bases: openai-compatible / anthropic / responses / google / systemone (the System One wire is a decision-protocol executor, NOT a chat executor — it serves the decision surface natively, ADR-0008 §7, and is excluded from chat pools) / vendor plugin wires (e.g. `qoder` — a native vendor gRPC transport provided by an operator-installed model-service plugin; the plugin carries its own protocol documentation in its own repository).

### 3. The single candidate choke point

`executeCandidatePool` is the ONE execution funnel for every entry mode (auto/explicit/combo/escalation) — so per-key model-access filtering applied there covers everything, including tier-escalation tails into denied models (`orchestrator.ts:1316-1331`; `policyDenied` → honest 403, `:939-946`). Per-candidate sequence fixed: selectCredential (health+affinity+slack, ADR-0002/0004) → rate-limit PEEK → consuming breaker gate `canExecuteScoped` (the ONLY probe-consuming check on the request path) → outbound slot deduct → `registry.execute` with the chosen credential (unknown-selector throw unreachable — stale-binding recovery happens at the selection boundary, never as a 500) → scoped breaker record. Last candidate is forced free when every gate denies (all-unhealthy keeps the legacy no-prefix force); all-DISABLED is NEVER forced (a takedown outranks availability, ADR-0004).

### 4. Two-stage retry economics

- **In-place micro-backoff** against the SAME candidate (default 1 extra attempt, 200 ms + 100 ms jitter): a transient network/5xx blip retried on the spot preserves prompt-cache locality (a 10×-cost retry beats a failover prefill); cause-whitelist gated (`retryOnCauses` — `server_internal_error` excluded by default on purpose: an ambiguous 500 may have executed); short-RA 429 burst eligible; 401/402 NEVER in-place (unattributable / quota — go around now).
- **Failover chain walk**: auto attempts = `retry.failover.maxAttempts` budget; explicit models are NEVER substituted (chain of ONE — amended 2026-12, ADR-0014; `router_options.failover: true` is the only per-request opt-in); combo cap = chain length (their own composition is the contract); `tierCrossPolicy: same_tier_only | allow_escalate` — escalate mode adds a healthy `plus` tail ONLY to a `lite` chain; strict Anti-Downgrade: a higher-tier chain never gains a lower-tier tail (`:1227-1229,1311-1315`).
- Schema-assertion cascade (auto + structured output only): lite lead → LOCAL static assertion (zero extra LLM cost; JSON syntax/required/type/enum) → on failure escalate to `fallback.escalateTier` (plus|pro|ultra) with the failed output + `[System Assertion Error]` correction appended and temperature 0.1 — skipped entirely for explicit models, combos, and `router_options.disable_fallback`. Fallback is honest (cause carried in `reasonParams`), not a silent rescue. The lite lead stays buffered (its bytes may be discarded wholesale); the escalation leg's response IS the final answer (no re-assertion), so it streams under the direct path's commit-point contract and stamps `ttftMs`/`genMs` the same way (ADR-0008 §3).

### 5. Streaming is downstream-only re-chunking

The gateway executes NON-streaming upstream calls and re-chunks to the client as SSE (`chat-sse.ts:3-6`): role → content in 4-char chunks → tool_calls in 32-char chunks → final chunk with the real `finish_reason` + usage. Terminal payload is ENCODED BEFORE `beginSse` (never a double-terminate). Both transports implement `beginSse/writeSseChunk/endSse`; `X-OCR-*` headers ride the SSE leg identically. Client-gone is detected per-leg and recorded as a synthesized 499 (nginx convention) — never sent upstream. MITM traffic not matching the surface table bypasses everything as a raw bidirectional splice (hop-by-hop headers stripped both ways; ADR-0008).

### 6. Token-saver compression family — three stages, all fail-open

`applyCompression` before routing (`compression/index.ts:36-75`): ① **rtk** tool-output compression (git/grep/ls/logs/build patterns; deterministic ⇒ same bytes same cache key); ② **headroom** sidecar proxy (`POST /v1/compress`, session-sticky by the gateway's OWN sessionId ⇒ replayed prefixes stay byte-stable; fail-open); ③ **caveman** output-style injection (idempotent system-message append; `lite|full|ultra|wenyan-*` levels; constraints verbatim-preserve code/paths/commands/URLs/errors, restore full sentences for safety warnings, keep the USER's language). The **pre-compression fingerprint principle** closes the loop: clients always resend ORIGINAL bytes, so session anchors index the pre-compression snapshot (`orchestrator.ts:491-505`; identity in ADR-0002) while the upstream compressed prefix stays stable through determinism + session mode.

**Sidecar lifecycle — association, not ownership** (`compression.headroom.autoStart`, opt-in default false): at boot the gateway probes `<url>/health` and ADOPTS any already-running instance; only when nothing answers does it spawn `headroom proxy --host 127.0.0.1 --port <from url> --mode cache` DETACHED (loopback URLs only) and poll readiness (≤20 s) without ever blocking the request path — fail-open carries traffic meanwhile, and a sidecar still mid-startup is adopted by the next probe. The spawned pid is recorded at `<home>/headroom.pid` (process-level file, ADR-0007 convention) and the gateway NEVER kills the sidecar on exit: headroom's session-replay state is exactly what keeps upstream prefixes byte-stable across the gateway's own controlled restarts (ADR-0007), so the sidecar is designed to outlive the gateway. Console surface: `GET /api/admin/headroom/sidecar` + `/start` + `/stop`. Stop works regardless of who started the instance: a gateway-recorded pid is killed directly, and a manually started LOCAL instance is identified by port (`Get-NetTCPConnection` / `lsof`; loopback only — the /health probe just confirmed that port serves headroom) and killed the same way; refusals stay honest — remote instances (`not-loopback`) and unidentifiable listeners (`pid-unknown`) are reported with machine codes the console localizes, never guessed.

### 7. Cost truth without savings theater

Per-request cost = uncached×input + cached×`cache_read` + output (+ reasoning premium only when the model prices it) (`request-cost.ts:13-39`). `cache_read` is a CATALOG price (fallback `input×0.25`) — no hardcoded discount constant. Baseline/savings are DELIBERATELY not computed (the legacy `savedCostUsd` field is stripped on replay): a counterfactual baseline is not a measurement. FinOps tier/token/latency aggregates live IN-PROCESS; only `totalRequests`+`fallbackCount` persist (`finops_totals` in the shared `traces.db`, WAL, own handle — fault-isolated from trace writes). Exposure: the trace `finops` block + `GET /api/admin/metrics` (+reset). There are no `X-OCR-FinOps-*` headers.

### 8. Observability plane of the execution path

TraceTracker: ring 5000 + per-env `traces.db` (WAL) persistence, retention 7 d / 100 MB, hourly sweep; record = request summary (safe `clientHeaders` subset) + routing (reason/reasonCode/reasonParams incl. eviction attribution, ADR-0002) + execution + finops. Admin surfaces: traces (ring→db, cold sessions rebuildable from persisted traces), sessions (live rows joined), logs (ring buffer tail ≤ 5000). Fastify per-request access logging is DISABLED by design (UI polling noise; 5xx floor kept via onError) — request observability is the trace/capture plane's job, not stdout's. The capture seams are named `observability/http-exchange` (client leg) + `observability/upstream-events` (`UpstreamEventContext` threaded through `process()`, provider-side emit contract) — no other event-sink abstraction exists.

Latency vocabulary follows the industry TTFT/TPS split (OpenRouter: `Total = TTFT + output tokens / TPS`), measured ONCE at the wire and derived everywhere. The trace execution block carries `ttftMs` (process start → the committed attempt's first forwarded chunk — user-perceived, routing/queueing/prefill AND any failed attempt before the commit included) and `genMs` (first chunk → stream fully drained — the decode window). The capture plane stamps the same moments per leg: streamed response events (both legs) carry `firstByteTs` (upstream SSE reader / gateway SSE write), and `CaptureTurnSummary` derives per-leg `ttftMs`/`genMs` from it.

**Console metric vocabulary (2026-11 revision; amended 2026-12 for the perceived stall-ratio metric) — three published metrics, none invented.** TTFT and output speed follow the OpenTelemetry GenAI semantic conventions so each console figure maps onto a standard instrument without translation; stall ratio borrows the streaming-QoE "rebuffering ratio" and is labelled as an experiential figure with no OTel GenAI equivalent:

- **TTFT** (`gen_ai.server.time_to_first_token`; vLLM `time_to_first_token_seconds`) — per-turn `ttftMs`, reported as **P50 and P95 percentiles**, never an arithmetic mean. A latency distribution is long-tailed: one 30 s cold start drags a 20-turn mean past anything a user experienced, while P50 stays at the typical turn and P95 carries the tail. This is what every published latency table reports (Artificial Analysis: median + P95; OpenRouter: P50).
- **Output speed** — output tokens ÷ the decode window (`genMs`), the inverse of `gen_ai.server.time_per_output_token` (vLLM `inter_token_latency_seconds`). Aggregated token-weighted (`Σtokens ÷ Σwindows`), never as a mean of per-turn rates.
- **Stall ratio** (`stalledMs` per turn, `stallRatio` per session; console label "stall ratio", the zh-CN table carries its localized name) — the share of streaming time the client spent waiting inside pauses of ≥1 s between two consecutive chunks carrying streamed output, inside the committed attempt's stream. Streamed output = answer text, tool-call fragments, **and reasoning/thinking deltas** (`reasoning_content` / `reasoning`): the relay forwards reasoning verbatim (`utils/chat-stream.ts`), so excluding it would charge a reasoning model's entire thinking phase as stall time. Role-only openers, `finish_reason` frames and the trailing usage frame are NOT output. Pauses are summed per turn (`stalledMs`), then divided by the summed decode windows over the session's measurable turns (`stallRatio`) — the same quantity as the video-streaming QoE rebuffering ratio, applied to the stream the client receives. A SHARE rather than a maximum, so repeated short stutters and one long freeze land on the same scale and answer length does not skew the figure — the dimension a longest-gap max could not express, and the reason the earlier max figure was replaced rather than extended. `stalledMs` is undefined ('—') for non-streamed turns and for streams with fewer than two output chunks; `0` is a measured smooth stream. Coloured amber at a 10% share. Measured at the gateway's relay, so client-side paint and network jitter are outside the window.

The window boundaries are part of the metric, so they are stated wherever the number appears: our speed figure EXCLUDES TTFT, matching OTel's `time_per_output_token` and Artificial Analysis' per-query speed, while OpenRouter's `Throughput` runs request-sent → last token and therefore INCLUDES it (its figure reads lower for the same model — the two are not comparable).

**No "prefill rate" is published.** Prefill is a server-internal measurement (`vllm:request_prefill_time_seconds` paired with `vllm:prompt_tokens_total`); a proxy sees only TTFT, which fuses queueing, network RTT, provider queue, cache read, prefill and the first decode step. Any rate built as `input ÷ TTFT` would track cache-hit ratio rather than model throughput (a 99%-cached session reads ~100× higher than a cold one on the same hardware), so it is neither shown nor named after a phase the gateway cannot observe.

The console's speed figures divide output tokens by the decode window only, on BOTH planes; the end-to-end story stays on the latency columns. Buffered single-shot exchanges carry no stamp and render '—' — a decode rate is never synthesized from full latency.

## Consequences

- One execution funnel ⇒ security filtering, breaker accounting, and rate deduction have exactly one home; entry-mode differences are POLICY fields on the same mechanism.
- Cache economics are explicit at each layer: in-place retries, deterministic compression, session-sticky sidecars, byte-stable fingerprints — and cost numbers stay measurements, never marketing.
- Degradation is loud: exclusions reported, fallback causes carried, empty pools warned.
