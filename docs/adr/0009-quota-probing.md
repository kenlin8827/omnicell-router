# ADR-0009: Quota Tracking — Layered Knowledge, Declarative Probing with Banned Classes, Credential-Anchored Activation

## Status

Implemented — 2026-10-15. Scope: how the gateway learns and displays the remaining allowance of every (providerId × keyHashPrefix) pair, what a probe may look like, where probe knowledge lives, what a probe failure may and may not do, and which surfaces consume it. Credential identity / key-exit discipline = ADR-0006; breaker vocabulary = ADR-0004; environment layout = ADR-0007; trace attribution = ADR-0005/0008.

## Decision

### 1. The principle: coverage follows the release, activation follows the credentials

Quota state is tracked per **(providerId, keyHashPrefix)** pair — the same display-safe credential identity pair breakers and credential flags anchor on (ADR-0006 §6). Two decoupled axes:

- **Coverage** — which providers *can* be probed — ships with the release (built-in table §3 + built-in code adapters §4) or with the operator's config (§5). It never snapshots the current credential pool: credential sets churn daily; the knowledge of a provider's quota endpoint does not.
- **Activation** — whether a probe is actually scheduled — follows credentials: a covered provider whose credential appears anywhere in the bound store (or the config-baked inference key, chain-less degeneracy) is armed automatically on the next scheduler pass. No credential-pool enumeration ever gates coverage.

Activation reads the **bound credential store** directly (`resolveKeyChain`), never the routing model registry: model registration is a routing concern, and a covered provider whose model list is still empty ("nothing maintained yet") still owns keys that must be probed. The registry chain is the fallback for a boot that bound no store; the config-baked inference key covers the chain-less degeneracy. Every surface that enumerates the pair directory (§9) uses the same union — a model-derived enumeration is the one shape that silently hides connected credentials.

The quota plane is **display-only**: a declared or probed cap never gates routing. Configuration staleness must not evict a healthy pair; takedowns stay owned by the breaker plane (below), which acts on *inference-side* evidence, not on probe-side aggregates.

### 2. Data model

```
QuotaSnapshot { providerId, keyHashPrefix, windows[], plan?, source, verifiedAt, entryId, lastFailureAt? }
QuotaWindow   { name, used, total, remainingPct, resetAt, unlimited }
QuotaProbeFailure { reason ∈ network|timeout|status|shape|auth, statusCode?, message? (upstream words, else the transport/credential cause), at }
source ∈ probed | measured | declared | forked
badge  ∈ probed | declared | unverified | stale        (console-visible four states)
```

The failure verdict lives in its OWN table keyed like the snapshot (not inside it): a snapshot is a value with windows, a failure is the absence of one — and a pair that never succeeded has no snapshot to hang it on. It is durable (same file, `failures` map) for the same reason the snapshot is: "why is this covered pair empty" must survive a restart. Contents stay display-safe: the transport reason, the HTTP status, and the upstream's own short message (the full body is already operator-visible through the last-probe dialog).

Known lossy by design in v1 (accepted, recorded here rather than modeled): per-window `currency` / `isCreditBalance` (multi-currency prepaid balances flatten to a credit-pool window: `used 0 / total = live balance`), and recurring-window metadata. `measured` is the reserved provenance of the phase-2 header-harvest layer (L-a below); `declared` is reserved for static plan-cap knowledge. Badge mapping: no snapshot → `unverified`; `declared` source → `declared`; last attempt failed or older than the entry cacheTtl → `stale`; else `probed`.

Storage discipline: snapshots are credential-anchored display-safe aggregates, so they live at the **GLOBAL** state root (`<OCR_HOME>/quota-snapshots.json`, atomic temp+rename 0600, load-once, debounced save — the suspect/disabled flags precedent, ADR-0006 §7), *not* the per-env book-set: an credential's quota belongs to the credential wherever it is used. Key material never enters the file (prefixes and numbers only). The **last raw probe exchange** (url/status/parsed body — never response headers, oversized or non-JSON bodies truncated to text) is a MEMORY-ONLY side table on the same store and is never serialized: it feeds the console's per-pair "inspect last probe" dialog and starts empty after a restart.

### 3. L-b: the built-in declaration table (DSL-driven, ships with the release)

Provider endpoints differ along at least six axes (auth header form, error semantics, value types, currency source, window granularity, naming) — there is no standard. A per-provider if-chain would rot; the table is **declarative**, interpreted by one engine (`quota/dsl.ts`). Every entry: one provider (OCR **catalog** provider id — keys were cross-checked against `catalog/ocr.json`; foreign id namespaces are not adopted), one URL, GET, static headers, a window-extraction table.

Host + auth disclosure (the table is trusted release code; absolute URLs and non-inference headers are permitted for built-ins — each choice named here):

Cross-check rule (applied before an entry ships): find the provider in `catalog/ocr.json` → verify the quota endpoint's origin belongs to the same provider's own domain → only then table it. Providers failing the check (e.g. `qoder` — not in the OCR catalog at all) are excluded.

The kimi entry reads TWO windows off its one response: the weekly quota from the top-level `usage` object, and the rolling 5-hour session cap from the first `limits[]` row (`{ window: { duration: 300, timeUnit }, detail: { limit, used, remaining, resetTime } }`) — the session window is identity-gated on `window.duration = 300` (a `where` equality, so a non-session row can never wear the session name), and a descriptor-only row (a fresh window carrying no `detail` fields) drops by the no-values rule rather than fabricating a bar.

### 4. L-c: built-in code adapters (one file per provider)

Providers whose semantics cannot be expressed declaratively land as code adapters (`quota/adapters/`, mirroring `providers/`). v1 ships exactly one: **MiniMax** (`minimax`, `minimax-cn`, `minimax-coding-plan`, `minimax-cn-coding-plan`). Reason: a two-URL fallback chain whose members carry **inverted count semantics** (counts on a `/coding_plan/` endpoint read as REMAINING, on `/token_plan/` as USED) plus relative-vs-absolute reset fields and percent-only shared buckets — "per-URL inverted mapping" is a banned table class (§6), and an entry is one URL by iron rule. Adapter facts (URL order per region, envelope `base_resp.status_code`, snake/camel field pairs, fallback triggers 404/405/5xx, key-invalid verdicts 401/403/1004) were **self-recorded into the adapter's header fact sheet before implementation**; the code follows the sheet, not the reference project. Region is a property of the provider-id **segment** (`-cn` anywhere in the id), never a config knob — an `endsWith('-cn')` test silently missed `minimax-cn-coding-plan` and sent its China key to the global host, where the key reads as invalid (an auth verdict, so no URL fallback) and the pair could only ever show `unverified`. Backlog (named, deferred): Copilot / Zed / Kimi-OAuth channels — their auth requires minting or device flows (not an inference-shaped header), so they can never enter the config table either; adapters only, when demanded.

### 5. L-a, L-d and L-e: the reserved harvest layer, the operator table, the plugin layer

- **L-a (phase 2, data plane reserved only):** `x-ratelimit-*` headers harvested from inference responses (the capture plane preserves response-header NAMES and redacts only credential-shaped values, so the `x-ratelimit-*` trio survives capture — ADR-0008 §5) ride the per-turn attribution that landed in `ExecutionTrace.execution.credentialKeyHashPrefix` (step-1 foundation: orchestrator stamps the SERVED credential — the same default-credential degeneracy as the ratelimit credential subject; SQLite needs no DDL because trace rows are JSON blobs and old rows replay the field as `undefined`, the `clientHeaders` forward-compat precedent). Nothing writes `source: measured` yet.
- **L-e (plugin knowledge layer):** a model-service plugin MAY declare the `quotaCheck` capability on `ModelServicePlugin` — the same contract as a code adapter (`QuotaAdapterContext` in, `QuotaProbeOutcome` out; raw key in-process only). Coverage resolution runs BY WIRE: the provider def's npm/baseURL resolves to a wire, the wire's loaded plugin that declares `quotaCheck` covers every credential-bearing provider on that wire. Precedence is the lowest layer — a built-in table/adapter (L-b/L-c) or an operator `quotaProbes:` entry (L-d) always wins; the plugin fills ONLY providers no higher layer covers. The plugin owns the endpoint knowledge (its own repository, its own protocol docs); core owns scheduling, the 429 backoff, the store and the display vocabulary. Absent capability or absent plugin = no coverage, indistinguishable from an uncovered provider (deliberate — the console shows no rows, not `unverified`). The motivation case is the vendored `qoder` gRPC wire, which is structurally excluded from the built-in table by the §3 cross-check rule (not in `catalog/ocr.json`) yet needs quota parity once its plugin is installed.

### 6. The DSL: twelve constructs, five banned classes

Constructs (each resolvable without computation): windows in three forms (static named / `each` over an array / `eachObject` over a keyed map); `firstOf` candidate paths; the **2-of-3 derivation** (any two of used/total/remaining imply the third); `invert` against a constant; `scale` (ratio → percent); `where` gates (**presence / equality / membership / boolean-truth only**); name resolution by pure `{field}` interpolation + literal `enumMap` (+ fallback), carrying an optional opaque i18n identity (`enumCode`/`code`/`argPath` and window-level `nameCode` → snapshot `nameCode`/`nameArg` — codes the console's translation table maps to localized labels, never computation); a static headers block; `successIf` (single equality against a body field); `refusalIf` (the same gate shape, naming the body field that states a plan-level refusal — see the verdict rule below); `unlimited` (literal or boolean path); `source: headers`; time parsing (epoch seconds/millis by magnitude, ISO, date-only). Absent-total degeneracy ("no stated cap") is a PRESENCE rule, not a value predicate. The single value predicate that DOES exist lives outside the DSL, at the store boundary in `probePair`: a NEGATIVE `total` is a vendor sentinel for "no stated ceiling" and is rewritten to `total: null, unlimited: true` — with the `remainingPct` that was computed against the fake cap dropped — for every source, entry or adapter, so a sentinel can never reach the console as a number (`0 / -1`). Reading a vendor's availability gate (`available: false` → emit no window at all) stays the adapter's job at its own boundary.

**Banned classes** (rejection is structural — the schema has no way to spell them — and the loader additionally rejects unknown keys so nothing smuggles in; a violating entry is dropped WHOLE, loudly):

1. arithmetic expressions (no `+ - * /`, no computed fields — literals and paths only);
2. cross-call data injection (stateless per-response resolution; no inputs from previous calls or other pairs);
3. value comparison / regex / time-delta predicates (`where` accepts `exists` / `eq` / `in` — nothing else; "exists may be selected, value conditions may not" is the control line);
4. per-URL inverted semantics (one entry, one URL; inverted families go to code adapters);
5. header value interpolation (headers are static strings; `{...}` in a header value is refused at load).

**Iron rules (L-d only):** a) relative-path sanitization — `..`, `//`, `@`, schemes rejected, and post-resolution the URL must sit inside the provider's inference baseURL origin; b) auth is inference-reuse `Bearer` — a provider whose quota call needs assembled/scheme-swapped/derived headers is disqualified from the table (built-in adapter only); c) GET-only, one URL per entry, cacheTtl clamped [60 s, 24 h] (429 backoff is engine-level global, §7); d) a config entry must NEVER silently shadow a built-in — replacing one requires `override: <builtinId>`, and a fork carries lineage (`forkedFrom`, `verifiedAt`); e) the banned-class validation runs at load; failures are surfaced on the console (`/api/admin/quota.rejected`), never swallowed. Prototype-shaped provider ids and `__proto__/constructor/prototype` path hops are rejected on sight (ADR-0006 pollution discipline).

### 7. Scheduling

Due-based, shaped after the active health prober (idea, not code): a fixed tick (default 60 s, `quota.intervalMs` clamped [10 s, 1 h]) plans this cycle's probes WITHOUT side effects (pure plan, assertable), then runs them sequentially; each pair's next due date = verifiedAt + entry cacheTtl with ±15 % jitter; ≤ 6 probes per tick. First sighting of a covered credential schedules immediately (that IS activation-follows-credentials). **Any 429 from any probe arms an engine-level GLOBAL backoff** (exponential, 5 min base, 3 h ceiling) that pauses the entire scheduler — quota endpoints are shared infrastructure; one capped response means everyone slows down. The kill switch `quota.enabled: false` stops all outbound probing; snapshots on disk still display (staleness logic unchanged).

The console's manual refresh does NOT touch that cadence: it invalidates the due dates (one pair, or the whole schedule) and then runs ONE extra cycle *inside the request*, so the page that awaits it can re-read fresh numbers instead of waiting for the next tick. That cycle is deliberately bounded — a 12 s wall-clock budget and an 8 s per-probe timeout, the per-tick cap does not apply (a human asking for fresh numbers gets all covered pairs) — and anything the budget cannot reach stays due for the regular tick. The 429 rule still wins: an armed gate refuses the manual cycle, and a mid-cycle 429 stops it. Cycles are exclusive — the manual path takes the same slot as the tick; a tick firing while a cycle runs SKIPS (never queues: due state survives, the next tick re-plans it), and a manual refresh finding the slot busy waits only up to its own budget and then answers `busy` instead of hanging the request. The interval timer is never restarted: due dates, not tick phase, express the cadence, so a manual refresh re-arms exactly like a tick and the next tick simply finds nothing due.

### 8. Failure semantics and the routing-plane firewall

**A verdict is decided from STRUCTURED signals, never from prose.** `QuotaProbeFailure.reason` names the transport shape (`network` / `timeout` / `status` / `shape` / `auth`) and is useless to an operator: a plan that expired and a subscription that was never opened both arrive as `shape` at HTTP 200. So the same record carries a closed `verdict` — `credential-rejected` / `plan-inactive` / `endpoint-gone` / `rate-limited` / `upstream-error` / `unreadable` / `unreachable` / `timeout` — plus the upstream's own `upstreamCode` as evidence (`quota/verdict.ts`). Assignment order: an adapter's stated conclusion (MiniMax reads `base_resp.status_code`: 1004 → `credential-rejected`, any other non-zero → `plan-inactive`), then the declaration table's `refusalIf` predicate, then the HTTP status (401/403 → rejected, 404 → gone, 429 → rate-limited), then a structured envelope refusal (`success: false` / non-zero `code`), then the transport reason. **Message wording NEVER decides a verdict** — quota endpoints answer in vendor prose, in the vendor's own language, and a wording rule would need one copy per vendor per language and rots the moment a vendor rephrases. The sentence travels as evidence (`message`, rendered verbatim, prefixed by `quotaPage.upstreamSaid`) while the verdict travels as a code the console translates once into all eight locales. The motivating case is Zhipu, which answers HTTP 200 with `{"code":500,"msg":"当前用户不存在coding plan","success":false}`: `success: false` is the machine-readable field, declared in the table as `refusalIf: { where: { path: 'success', truthy: true } }` (a load-validated construct of the ordinary `where` grammar — presence / equality / membership / `truthy`, still no comparison, no regex), and the localized `msg` beside it is never matched. The matching frontend rule is the mirror of this one: `frontend/src/lib/quotaFailure.ts` only maps a verdict code to an i18n key and never inspects `message`.

**Probe failure ≠ quota failure.** A failed attempt never reaches the circuit breaker, never marks SUSPECT, never disables, never enters the trace table: the previous snapshot is kept and `lastFailureAt` flips the badge to `stale`; a pair that never succeeded keeps no snapshot and stays `unverified` — but it now also keeps WHY (the `QuotaProbeFailure` verdict: reason + HTTP status + the upstream's own message). Without that verdict a covered pair whose credential was rejected (401) or whose plan is inactive (MiniMax `base_resp.status_code: 2062 "no active token plan subscription"`, at HTTP 200) was indistinguishable from "the first sync has not run yet" — the console could only repeat `unverified` forever, which is a lie. The four badge STATES are unchanged; the console's state WORD is derived from the pair: a recorded failure reads "probe failed" (never "unverified"), and the failure caption is rendered wherever a pair has no numbers (quota page card, sidebar peek, per-credential tooltip). A successful attempt retires the verdict (stale evidence must not outlive the measurement). Conversely the quota plane consumes inference-side evidence in exactly one direction: every `QUOTA_EXHAUSTED` diagnosis recorded at the breaker manager's single failure join point (`recordFailureScoped`) lands one row in the **`quota_events`** ledger BEFORE rule gating (observability is not policy — turning quota *tripping* off must not blind the ledger). The ledger mirrors the ratelimit ledger discipline: ring 500, durable mirror in `traces.db` (`quota_events` table, independent WAL handle, fail-open, boot replay). The classifier gained the CN ceiling markers (quota wording + rolling-session-cap wording in the match literals) so Chinese-provider ceiling burns fold into QUOTA_EXHAUSTED (credential-scoped, 12 h floor, no SUSPECT — ADR-0004 vocabulary unchanged). Vocabulary firewall holds: `CLOSED/HALF_OPEN/OPEN` remain CircuitBreaker-only words; the quota badge states (`probed/declared/unverified/stale`) are a separate axis and are never reused as health terms. Ceiling takedowns continue to run through the existing pair-breaker trip semantics; `resetAt`-aligned cooldown shaping is phase 2.

**A failure names its cause.** `QuotaProbeFailure.message` comes from the upstream body when one came back, otherwise from `LastProbeCapture.detail` — one bounded line (`FAILURE_MESSAGE_MAX_CHARS`) with the error class, its message and the transport code parked on `cause` (`ENOTFOUND`, `ECONNREFUSED`, an abort). A reason code alone is not evidence: a bare `network` covered a dead resolver, a refused socket, an aborted request *and* a credential chain that never reached the quota endpoint (a leg whose clock ran out now has its own verdict — rule 5), so the bare word (rendered "network failure" in the console) hid the commonest case — the account had simply signed out. The rules that follow. (1) An adapter that resolves a credential chain before probing reports a chain rejection with its OWN class: a vendor 400 / 401 / 403 from a token exchange or device refresh is a credential verdict (`reason: auth`, its `statusCode` recorded), while 408 / 429 / 5xx stay transport — flattening a rejection into 502 to keep the story tidy is a bug. (2) A probe reads the credential it was asked about. Where a plugin persists one login per gateway (the qoder device bundle), that bundle must not answer for a DIFFERENT stored key: the console would print one account's numbers on every pair of the provider while the credential actually in rotation keeps its real ceiling invisible. Bundle-preference remains on the request path (a rotated bundle keeps the login alive); the probe opts out explicitly (`resolveAccessToken(key, gateway, { ownCredential: true })`). Ancestor tokens are the exception that proves the rule: the console writes a sign-in's access token into the credential store and the plugin then rotates it silently, so that stored row is a stale copy of THIS login, not a second account — the bundle records the predecessors it replaced (`DeviceCredential.rotatedFrom`, capped at `ROTATED_HISTORY`, carried across re-logins only while the uid matches), and a row found in that chain probes as its own login. A key outside the chain (a pasted off-box token) is answered for itself, and its rejection is the honest reading of that row; writing a rotated token back into the credential store needs a core host seam (ADR-0006) and is deliberately not done here. (3) The body is read BEFORE the verdict — on every outcome, not just the successful one — because a dead key answers 401 with a body that says so, and a capture that dropped it could render only the reason word. (4) An adapter is third-party code: a probe that REJECTS instead of returning its failure object still lands a transport verdict (`network`, or `timeout` when the clock ran out) with the cause and a capture (the adapter id stands in for the URL core never saw). Letting it escape killed the whole pair and every pair behind it in the cycle, which looks exactly like a probe that never ran. (5) A leg that never got an answer because its clock expired is `timeout` — `classifyThrownFailure` reads the timeout shapes Node/undici actually throw (`HeadersTimeoutError`, `BodyTimeoutError`, `ETIMEDOUT`, `timedOut: true`, and an `AbortError` carrying timeout wording), and the same rule is mirrored on the plugin side (`plugins/qoder-models/quota.ts`) because a plugin imports core types only. A bare `AbortError` with no timeout provenance stays `network`; but the transport CLASS never overrules the MESSAGE — the line takes the throw's own cause chain (the first readable text on it), because `AbortSignal.timeout`, an outer wall-clock abort and a fetch-resource timeout all surface as an unnamed `AbortError`, and only the site that threw knows why it was interrupted. What must never happen is the collapse the first pass allowed: Node names a wall-clock abort `AbortError`, the same name a credential-rejection path matches, so a hung gateway was being reported as a rejected key — and a false `auth` verdict sends the operator to re-auth a credential that was working. An HTTP ANSWER keeps its own class: a 504 is `status` ("upstream refused · HTTP 504"), because the upstream did speak.

### 9. Surfaces

Console: the `CredentialHealth` overlay (every credential-returning response, ADR-0006 §9 contract) gained an additive `quota?: CredentialQuotaView` — four-state badge, per-window bars with reset countdowns, provenance (`entryId`, `source`, `plan`, staleness) in the tooltip. Absence of the key means *not covered* — deliberately distinct from the `unverified` badge. A dedicated **Quota page** (`/admin/quota`) renders the cross-provider directory: every CONNECTED pair whose provider is covered (pair enumeration = the bound credential store's credentials ∪ the registry chains ∪ config-baked inference keys, display-safe prefixes only; uncovered providers render no rows) with its badge, window bars, plan, provenance and its attributed served-usage join (`getCredentialPairUsageStats` over the trace ring). The release coverage list (covered provider with no credential yet stays inspectable), the rejected `quotaProbes:` entries (validation failures are surfaced, never swallowed) and the recent burn-event ledger are served by `GET /api/admin/quota` as the diagnostics contract (`coverage / rejected / pairs / events`) — the page itself stays a single directory surface and does not embed those three lists. A pair's readable identity is the operator's credential label, or — for an UNNAMED credential — its masked key (`maskSecret`, the same string the credentials list shows, so "which key is this" is answered by what the operator actually pasted); a store machine id is never a display name (the chain label used to fall back to the `credentialId` UUID), and the display-safe key hash stays in the tooltip and the search. `GET /api/admin/quota` serves this contract (`coverage / rejected / pairs / events`); `POST /api/admin/quota/refresh` re-arms a pair or the whole schedule and then runs one BOUNDED probe cycle inside the request (§7 budget) — the page awaits it and re-reads, so a manual refresh shows fresh numbers without waiting for the tick. Both scopes are offered by the UI: the page header (whole schedule) and each pair card (that one pair — one upstream request, since quota is per provider × credential), plus the sidebar peek's copy of the global action. `frontend/src/lib/api.ts` mirrors these wire names 1:1 (`CredentialQuotaView`, `QuotaPairRow`, `QuotaWindow`, `QuotaBadgeState`, `QuotaSource`). Raw keys never appear on any surface (display-safe prefixes only); UI strings are all `t()`-fed.

## IP discipline (acknowledged constraint)

Endpoint facts, response shapes and window semantics for all table/adapter entries were verified against the providers' public API documentation and cross-checked against a public MIT-licensed reference implementation (deliberately unnamed in repo-visible text). From it, only *facts* (URLs, header forms, field structures, unit codes such as GLM's session/weekly codes) and *architecture ideas* (declaration table + adapter registry, multi-window model, due-based scheduling) were taken — API contract facts are not copyrightable and ideas are not code. All OCR implementation, fixtures (synthetic, self-authored), comments and documentation are original English-language OCR text; no statement copied or line-ported from the reference project (red line: six-word contiguous matches against its source in a functional diff). Borrowed as facts, never as code.

## Consequences

- Adding a covered provider is a table row (with the §3 catalog cross-check + auth disclosure) when its semantics are declarative, a one-file adapter otherwise, an operator `quotaProbes:` entry for the long tail — the release grows, the runtime never needs to know the credential pool.
- The plugin layer (L-e) extends coverage to vendor wires the cross-check rule can never table: capability follows the plugin binary, activation still follows credentials, and precedence keeps release/operator knowledge authoritative. A plugin that ships without `quotaCheck` silently leaves its wire's providers uncovered — the honest state.
- The ban list is enforceable at load because it is structural: what cannot be spelled cannot run; bad operator entries fail loudly into `/api/admin/quota.rejected` instead of half-working.
- Quota visibility can never strand traffic: probe outcomes are display evidence only, and inference-side quota burns keep their existing breaker semantics with an added durable event ledger.
- Tests: `quota-dsl` (constructs, banned classes, per-entry fixtures), `quota-engine` (iron rules, plan merge, probe execution, MiniMax semantics, scheduler, events linkage, trace pairing).
